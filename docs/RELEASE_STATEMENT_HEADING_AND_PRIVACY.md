# Заголовок заявления и ссылка Inspectlet

Подготовленный выпуск по команде Ольги: перенос заголовка после шапки и одна
серая ссылка управления Inspectlet на `/privacy`. Новых миграций нет.
Публикацию и проверку на боевом сервере выполняет Ольга.

## Поведение

После штатного форматирования проверенные Google-координаты используются
для ограниченного восстановления порядка «шапка → заголовок/подзаголовок →
основной текст». Переносятся готовые блоки; значения, исходный OCR, таблицы,
списки и исправления не переписываются. Для неясной структуры, смешанного
текста, нескольких заголовков, неподтверждённых координат и обычных документов
правило не применяется. Результаты банковского обработчика пропускаются.
Дополнительных OCR/LLM-запросов нет. Старые обработанные записи автоматически
не пересчитываются; основной тест — новая обычная загрузка.

Свежие координаты поступают из проверки хэша изображения в recognizeAndCacheOcr.
При повторе оформления читается принадлежащий владельцу кэш с тем же хэшем.
Без явного подтверждения источника (`layoutVerified`) перенос не применяется.

На `/privacy` показывается один элемент управления:
«Запретить Inspectlet» при разрешении, иначе «Разрешить Inspectlet».
Внешний вид — серая подчёркнутая ссылка, управление доступно с клавиатуры.
Выбор проходит через существующий controller, сохраняется после обновления
и синхронизируется с другими вкладками. Загрузка/выключение самого SDK и
правила безопасности Inspectlet не менялись.

## Включение и отключение

Для боевого сервера нужен отдельный `STATEMENT_HEADING_ORDER_ENABLED=true`
в `server/.env`. `false` отключает проверку последующих обработок.
Без этого ключа сохраняется прежний локальный режим:
`LOCAL_STATEMENT_HEADING_ORDER_ENABLED=true` только с localhost-БД вне production.
Случайный перенос локального ключа на сервер не включает правило.

## Публикация: команды Ольги на сервере

```bash
cd /root/myworld &&
git pull --ff-only origin main &&
(
  set -e
  if grep -q '^STATEMENT_HEADING_ORDER_ENABLED=' server/.env; then
    sed -i 's/^STATEMENT_HEADING_ORDER_ENABLED=.*/STATEMENT_HEADING_ORDER_ENABLED=true/' server/.env
  else
    printf '\nSTATEMENT_HEADING_ORDER_ENABLED=true\n' >> server/.env
  fi
  npm run build --prefix client
  pm2 restart myworld-server --update-env
  curl -fsS http://127.0.0.1:4000/api/health
  pm2 status myworld-server
)
```

Миграции этот коммит не добавляет. Если на сервере не применены миграции из
более ранних выпусков, их статус проверяется отдельно перед обновлением.
После обновления страницы проверить одну ссылку `/privacy`, оба направления
переключения и новую загрузку заявления/обычного документа.

## Отключение переноса заголовка

```bash
cd /root/myworld &&
sed -i 's/^STATEMENT_HEADING_ORDER_ENABLED=.*/STATEMENT_HEADING_ORDER_ENABLED=false/' server/.env &&
pm2 restart myworld-server --update-env
```

Сохранённые результаты при отключении не меняются. Ссылка Inspectlet остаётся.
