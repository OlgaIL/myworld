## Состав

Добавить отдельный провайдер `timeweb` для LLM в standard pipeline.
OCR остаётся Google или Яндекс; fast image pipeline OpenAI не переделывать.
Gemini напрямую не интегрировать: модель выбирается в Timeweb Gateway.
Яндекс/OpenAI сохранить как самостоятельные провайдеры со своими ключами.

Переменные:

- `TIMEWEB_API_KEY` — секрет в private-env, не отдавать клиенту/логам.
- `TIMEWEB_AI_ENABLED` — явно включаемый флаг, по умолчанию выключен.
- `TIMEWEB_BASE_URL` — по умолчанию `https://api.timeweb.ai/v1`;
  отдельный endpoint, не менять `OPENAI_BASE_URL` для подключения Timeweb.
- `TIMEWEB_MODEL` — задаётся явно; первый пример `openai/gpt-4.1-mini`:
  Ольга предложила проверить GPT через Timeweb. Gemini можно выбрать другим
  значением через env, без привязки к одной модели. GPT-4o mini в публичном
  каталоге Timeweb остановлена; не выбирать её как рабочий пример.
- `TIMEWEB_TIMEOUT_MS` — конечное положительное значение, ориентир 20000.
- `TIMEWEB_MAX_TOKENS` — конечный лимит; выбрать и обосновать значение
  с учётом JSON и возможных reasoning-токенов. Ориентир 6000, не обещать
  реальную себестоимость без usage-замера. SDK retries для Timeweb — 0.

Разрешить `timeweb` в `PROCESSING_STANDARD_AI_PROVIDER` и
`PROCESSING_GUEST_AI_PROVIDER` / `PROCESSING_FREE_AI_PROVIDER` /
`PROCESSING_PAID_AI_PROVIDER`. Выбор после изменения env и restart;
автоматического выбора другого провайдера при ошибке нет. Документировать
standard/override и значения для всех трёх аудиторий: общий default не
переопределит уже явно выставленные per-audience значения.

## Код и совместимость

1. Отдельный обработчик Timeweb: Chat Completions с явными baseURL/key/model,
   system/user prompt, контрактом JSON и общим безопасным парсером.
   Результат имеет `sourceText`, формат/метаданные как у существующего
   стандартного pipeline. Базовые промпты сохранить; по замечанию Ольги
   добавить отдельные Timeweb-инструкции corrections, не переписывать
   незавершённые чужие OCR правки.
2. Guard включения, проверка ключа/модели до внешнего запроса. Понятные
   ошибки: выключен, не настроен, auth/limit/timeout/network/invalid JSON,
   пустой или обрезанный ответ. Отказ сохраняет уже распознанный текст
   standard-ветки и не списывает успешную обработку; повтор без нового OCR.
3. Health/admin settings безопасно показывают Timeweb и выбранную модель,
   без ключа, без сетевого запроса к Timeweb на каждом health.
4. Логи LLM показывают именно `timeweb`, UI label «Timeweb». Новая миграция
   расширяет CHECK провайдера в `llm_attempt_events`; миграцию 031 не менять.
   Номер выбрать свободный. Не изменять историю записанных событий.
5. Отдельный диагностический CLI для синтетического текста: запускается
   явно человеком; читает конфигурацию, выполняет один полный запрос через
   адаптер, проверяет JSON/результат. Не загружает документы из БД, не
   выводит ключи или личные данные. Для первых проверок достаточно текста;
   цены/usage сохранять, если они доступны, без содержимого документов.
