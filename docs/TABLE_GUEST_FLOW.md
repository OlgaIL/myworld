# Переход гостя к восстановлению таблиц

Локальная итерация от 1 ноября 2026. На сервер агент не подключался.

## Поведение

- Промо `/table-from-photo` передаёт `/?intent=tables`. После гостевой загрузки
  открывается документ с выбранной вкладкой «Таблицы», если она доступна.
- При обнаруженной таблице гость видит вкладку и кнопку «Войти и восстановить
  таблицу». Кнопка раскрывает способы входа; выбор провайдера сохраняет намерение
  для конкретного документа после принятия существующего соглашения.
- После входа существующий механизм переноса сохраняет фото, OCR и координаты
  в аккаунте. Повторная загрузка и повторный Google OCR не требуются.
- Первая сборка запускается автоматически один раз при доступной попытке.
  Готовая таблица открывается без повторной сборки. Предыдущая попытка, незавершённая
  основная обработка или отсутствие доступа исключают автоматический запрос.
- Намерение хранится в sessionStorage текущей вкладки до 30 минут и удаляется
  перед запросом. Ошибка, обновление страницы и повторное монтирование React
  не вызывают автоматический повтор. Новый обычный вход отменяет прежнее намерение.
  При недоступном хранилище остаётся ручной запуск. URL выбирает вкладку, сам
  по себе URL не разрешает вызов модели.
- Под готовой таблицей с отступом 24 px расположена подсказка: «Здесь только
  таблицы, можете скопировать только их». Со следующей строки: «Чтобы увидеть
  полный текст с таблицами и скопировать всё, переключитесь во вкладку
  „Оформленный“». Название вкладки открывает весь документ.
- Открытие документа из списка всегда начинает страницу с (0, 0). Единый
  DocumentNavigationScroll сбрасывает обе координаты до отрисовки при смене
  pathname для гостевых документов и аккаунта. Обновление данных, смена
  вкладки/query не сбрасывают позицию читателя. Проверено Browser Plugin:
  списки на 3052/5802 px, задержка загрузки и переход между документами;
  обновление/query сохраняют 6466 px. Предыдущий сброс промостраниц документов
  не касался; отдельный гостевой useEffect заменён общим обработчиком.
  Доступ, число попыток, оплата и серверные проверки сохранены.

## Локальная проверка

28 адресных Node-тестов, ESLint затронутых компонентов и production-сборка клиента
прошли. Browser Plugin проверил реальный App с синтетическим адаптером API:
вход по email, возврат с внешнего входа (имитация), одну сборку и отсутствие
повтора после обновления/ошибки, готовый результат, отсутствие доступа/таблицы,
disabled при recognized, обычный вход без сборки, промо и переход к полному тексту.
Мобильная ширина проверена на отсутствие горизонтального переполнения.
По замечанию Ольги кнопки входа/сборки переведены на существующий светлый стиль
с рамкой; общий стиль способов входа больше не перекрывается. Кнопки feature-промо
также светлые. Browser Plugin подтвердил цвета стандартной кнопки, входа,
провайдеров и сборки; проверено состояние загрузки. Сборка и ESLint прошли.
Платных вызовов и реальных писем не было. Временная тестовая страница удалена.

Ручной тест Ольги на локалке: открыть `/table-from-photo` без входа, загрузить
таблицу, выбрать «Войти и восстановить таблицу», войти. Ожидается тот же документ,
автоматический прогресс и результат. Затем перейти по ссылке «Оформленный» и
сверить весь текст. Отдельно проверить реальный Яндекс/VK: переход к внешнему
провайдеру в автоматической проверке заменён имитацией возврата.

## Публикация Ольгой после ручной приёмки и отдельного коммита

По поручению Ольги общая публикация 1 ноября включает также `015bff5`
(`Show account details in Clarity recordings with renewed consent`). Коммит
проверен: уже входит в локальную main, переносить его cherry-pick не нужно.
Единая клиентская сборка включает обе правки после коммита гостевого пути таблиц.
Для Clarity дополнительно выполнить ручную проверку нового согласия v3,
имени/почты/аватара и скрытия полей входа/админки по [CLARITY.md](CLARITY.md).
Push/получение этого коммита сервером и публикация пока не подтверждены.

Меняется только клиент. Новых зависимостей, миграций и переменных `.env` нет.
Сначала локально отправить согласованный коммит:

```powershell
cd C:\Users\olgak\PROJECTS\myworld
git push origin main
```

На сервере:

```bash
ssh root@147.45.246.205
cd /root/myworld
git status --short
```

Если есть изменения на сервере, сначала разобрать их; не выполнять reset/clean.
При чистом состоянии:

```bash
git pull --ff-only origin main
cd /root/myworld/client
npm run build
```

Для клиентской правки миграции и перезапуск PM2 не требуются. После сборки
Ольга проверяет `/table-from-photo` без входа с обновлением страницы и выполняет
ручной путь до готовой таблицы, затем переход к «Оформленный». Обычный вход
должен сохранить прежнее поведение. Агент production не проверяет.
