# Резерв при недоступности API Яндекса

11 октября 2026. Ольга поручила добавить Timeweb как отдельного провайдера
с ручным выбором через env. Автоматический fallback пока не делать.
ТЗ: `docs/TIMEWEB_MANUAL_PROVIDER_TASK.md`.
Причина риска: техническая недоступность Яндекс API. Ольга подтвердила,
что прямой OpenAI с нашего сервера без VPN недоступен. Этап 1 админки
приостановлен пользователем; разработчик ещё не запускался.

## Что уже есть в коде

- OCR и LLM разделены в standard pipeline. OCR поддерживает Google и Яндекс,
  LLM — Яндекс и OpenAI. Автоматического переключения между ними нет.
- При успехе OCR и ошибке LLM standard-ветка сохраняет распознанный текст
  (`recognized`) и позволяет повторить оформление. Текст не теряется,
  успешная обработка в этой ветке не списывается до полного результата.
  Это не защищает от отказа самого OCR и не относится к fast image pipeline.
- Провайдеры задаются отдельно для guest/free/paid в конфигурации;
  перезапуск нужен, потому что значения читаются при старте.
- Установленный OpenAI SDK читает `OPENAI_BASE_URL` из окружения.
  `aiService.js` создаёт SDK-клиент без явного baseURL, поэтому изменение
  этого параметра позволяет направить существующий Chat Completions запрос
  на другой совместимый API. Возможность подтверждена по локальному коду
  SDK, а не живым запросом к резервному сервису.
- Нынешний запрос использует JSON mode, system/user messages, temperature,
  max_tokens и собственный разбор результата. Совместимость конкретной модели
  со всеми этими параметрами должна быть проверена, а не предположена.
- SDK по умолчанию может долго ждать и повторять запросы. Для настоящего
  оперативного резерва нужны явные timeout/retry и общий бюджет времени.

## Варианты для согласования

1. Timeweb AI Gateway: совместимый Chat Completions API с единым ключом.
   Первый кандидат для быстрой проверки, поскольку приложение использует
   такой же интерфейс. Выбрать модель из доступного каталога и проверить
   точный контракт JSON, русский текст, задержку и стоимость.
   Endpoint: `https://api.timeweb.ai/v1`. Ключ требуется именно Timeweb,
   имеющийся ключ OpenAI не подходит. Это отдельная услуга, готовность
   доступа и баланса текущего аккаунта не подтверждена.
2. Cloud.ru Foundation Models: второй кандидат для независимого резервного
   API. Совместимый формат заявлен в документации; модель/ключ/доступ
   уточнить по текущему каталогу и тесту, не считать уже подключёнными.
   Endpoint: `https://foundation-models.api.cloud.ru/v1/`.
3. GigaChat API: альтернативный поставщик. Нужны отдельная интеграция
   авторизации/ответов и проверка наших документов; это не замена простым
   выбором `openai` в текущем приложении. Рассмотреть как второй резерв.

Успешный тест с ноутбука не доказывает доступность с веб-сервера.
Локальные синтетические тесты готовит агент, проверку с production выполняет
только Ольга по согласованной инструкции; не отправлять реальные документы
новому поставщику для первых проверок.

## Рекомендуемая последовательность

Дополнение 11 октября: Ольга попросила оценить Google/Gemini и собственный
промежуточный сервер. Google Vision OCR уже поддерживается; Gemini как LLM
пока не интегрирована. Timeweb заявляет Gemini в каталоге, поэтому сначала
можно проверить Gemini через тот же шлюз. Свой шлюз технически возможен:
Word2you → закрытый сервис с авторизацией → Google API. Он требует отдельного
хостинга, ключей/биллинга, timeout/retry, мониторинга и соблюдения условий
выбранного Google API. Смена IP не доказывает допустимость регионального
доступа аккаунта и пользователей. Не смешивать Gemini API/AI Studio,
Vertex AI и уже работающий Vision OCR — условия и подключения разные.
Создание промежуточного сервера не поручено; этот вариант только обсуждается.

1. До отключения получить доступ к одному резерву, выбрать модель и проверить
   синтетический текст полным запросом приложения. Сравнить небольшой
   согласованный набор документов, отдельно JSON и сохранность содержания.
2. После успешной проверки подготовить отдельный резервный профиль
   конфигурации и точные команды переключения/возврата. Для standard OCR
   оставить проверенный Google; менять только LLM. Проверить профили
   guest/free/paid и override: одной общей переменной может быть недостаточно.
   Не путать API-совместимость с непосредственным доступом к OpenAI.
   Не выдавать конфигурацию за проверенную инструкцию до теста.
3. Затем реализовать автоматический резерв: ограниченные timeout/retry,
   временное отключение проблемного провайдера после серии отказов,
   отдельный ключ и endpoint резерва, отдельная маркировка в LLM-метриках,
   уведомление в Telegram без потока одинаковых сообщений. Не менять
   глобальный endpoint в процессе запроса и не списывать обработку дважды.
4. Если недоступны оба LLM, сохранять OCR-текст и предлагать повтор позже.
   Отказ Google OCR — отдельный сценарий: резервный OCR/vision требует
   независимой проверки, особенно для рукописей. Резерв LLM его не покрывает.

До начала реализации ключи не менялись, внешние API не вызывались,
live-тестов и расходов не было. Выбран Timeweb, модель задаётся через env.
Получение ключа выполняет Ольга; live-готовность ещё не подтверждена.
Позже 11 октября ключ получен и сохранён в локальном env, наличие проверено
без вывода секрета. Ольга предложила первой проверить GPT через Timeweb.
Выбран кандидат `openai/gpt-4.1-mini`: в публичном каталоге активна;
GPT-4o mini остановлена. Интеграция остаётся модельно-независимой.

## Предварительная стоимость и объём работ — 11 октября

Цены из данных официального калькулятора Timeweb AI Gateway. Снимок
публичной страницы сохранён в `work/timeweb-ai-gateway-pricing.html`,
расчёт — `work/timeweb-ai-gateway-cost-estimate.json`. Это ориентир,
перед подключением сверить тариф в панели; скидки и кеш не учитывались.

| Модель | Вход, ₽/млн | Выход, ₽/млн | Один документ, ₽ | 1000 документов, ₽ |
| --- | ---: | ---: | ---: | ---: |
| Gemini 3.1 Flash Lite | 34 | 203 | 0,41 | 407 |
| Gemini 3.8 Flash | 101,25 | 506,25 | 1,06 | 1063 |
| DeepSeek V4.1 Flash | 40,50 | 162 | 0,36 | 365 |
| GPT 4.1 mini | 54 | 216 | 0,49 | 486 |

Расчётный документ: 3000 входящих токенов (включая инструкции) и 1500
оплачиваемых исходящих. Это сценарий, а не замер наших документов.
Дополнительные reasoning-токены, длинные документы и повторные запросы
увеличивают расходы. Формула: input_tokens * cost_in + billed_output_tokens
* cost_out. OCR Google оплачивается отдельно. Базовая стоимость на странице
Gateway — 1 ₽/месяц; отдельный VPS для Gateway не нужен.
На первичную проверку предложен бюджет 300–500 ₽, покупка не выполнялась.

Предварительная оценка рабочего времени, не обещание срока:

1. Доступ, ключ, две модели, синтетический полный JSON-запрос и набор
   согласованных документов: 1–2 часа при готовом аккаунте.
2. Отдельный резервный профиль, ограниченные timeout/retry, корректные
   метрики провайдера и понятная ошибка: 2–4 часа, если API совместим.
3. Локальные регрессии, гостевые/платные сценарии и инструкция переключения/
   возврата: 1–2 часа. Затем ручная публикация и проверка Ольгой.
4. Автоматический fallback, ограничение повторов, уведомления и сценарии
   двойного отказа/восстановления: отдельный этап, ориентир ещё 1–2 дня.

Первый ручной резерв — ориентир один рабочий день после получения ключа,
если совместимость и качество подтвердятся. Не начинать внедрение без
поручения Ольги. Отказ OCR и собственный зарубежный VPS сюда не входят.

Timeweb имеет дата-центры в Санкт-Петербурге, Москве, Новосибирске и за
рубежом. Это не устанавливает локацию AI Gateway и выполнения конкретной
модели. Точную локацию Gateway пока не подтвердили; у внешних Gemini-запросов
посредником выступает Timeweb, поставщиком — Google. На странице заказа
есть согласие на трансграничную передачу. Российские локальные модели
описаны Timeweb отдельно; условия выбранной модели проверить в панели.
