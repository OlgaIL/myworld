# Вкладка «Таблицы»: локальная проверка и публикация

13 октября 2026 года добавлено восстановление таблиц из фото документа.
Вкладка появляется при признаках таблицы. Зарегистрированный пользователь
без пакетного баланса может бесплатно восстановить таблицы в одном документе. Попытка
расходуется только после готового проверенного результата; ошибки и результаты,
отклонённые проверкой, её не расходуют. После пробной таблицы появляется
замочек; подарочные обработки в пакете дают доступ.
Повторное восстановление после успеха читает сохранённый результат. Новые
обработки с баланса не списываются. Миграция `038_document_tables.sql` хранит
структуру таблиц отдельно от обычного текста и разрешает учитывать запросы
таблиц в статистике LLM. Миграция `039_table_trial.sql` хранит использование
бесплатной попытки. Проверенные таблицы добавляются в «Оформленный», только
если их место однозначно найдено; иначе остаются в отдельной вкладке.

Локально проверены две таблицы с фото `better.jpg`: 9 и 8 столбцов, по три
строки, сохранена исходная ориентация. Сверка с координатами Google OCR
отвергает переставленные строки и столбцы. Проверены локальный API, отсутствие
списания баланса, тесты, lint и сборка. Перед публикацией Ольга проверяет
вкладку, замочек и вставку в Word/Excel в локальном браузере.

## Локальная проверка Ольгой

Открыть адрес, который вывел локальный Vite (обычно `http://localhost:5173/`).
Войти в аккаунт с оставшейся обработкой в пакете,
открыть распознанный документ с таблицей и вкладку «Таблицы». Нажать
«Восстановить таблицы». Убедиться, что годы остались столбцами, типы станций
строками; проверить обе таблицы и числа 216,8, 221,0 и 717,8. Скопировать
таблицы в Word и Excel, затем перезагрузить страницу и повторно открыть
вкладку: результат должен сохраниться, баланс пакета не должен измениться.
В бесплатном аккаунте одно успешное восстановление доступно без пакета. Проверить,
что после неё замочек появляется на других документах, а готовая таблица
остаётся доступной. При неуспешном восстановлении бесплатная попытка остаётся.
Проверить «Оформленный»: две готовые таблицы стоят среди обычных абзацев;
кнопка запроса улучшения находится под заменами внутри серого блока.
На квитанции с горячей водой повторить «Восстановить таблицы»: ранее сохранённый
статус `review` допускает повтор. Ожидается таблица с 6 столбцами и 6 строками;
сверить «ХВС», «Итого» и расчёты ниже таблицы в «Оформленном».

## Публикация Ольгой после приёмки и отправки коммита в main

Новая конфигурация env не нужна, если на боевом сервере уже работают
`TIMEWEB_AI_ENABLED=true`, `TIMEWEB_API_KEY`, `TIMEWEB_MODEL` и Google OCR.
Используется текущий Timeweb GPT‑4.1 mini. Сначала проверить, что ночная
резервная копия БД существует и подходит для восстановления.

```bash
cd /root/myworld
git status --short
ls -lh /root/myworld-backups/myworld-db-*.dump | tail -n 2
```

При неожиданных изменениях в рабочей папке остановиться и разобраться до
`git pull`. После проверки:

```bash
cd /root/myworld
git pull --ff-only origin main
git log -1 --oneline
cd server
npm ci
npm run db:migrate
npm run db:status
pm2 restart myworld-server --update-env
cd ../client
npm ci
npm run build
curl --fail --silent --show-error https://word2you.ru/api/health
```

В ответе health должно быть `"status":"ok"` и `"database":{"configured":true,
"connected":true}`. Затем в браузере повторить проверку вкладки и баланса
на тестовом документе. Боевую публикацию и проверку выполняет только Ольга.
