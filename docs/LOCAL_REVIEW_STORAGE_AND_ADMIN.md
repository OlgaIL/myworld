# Ручная проверка перед публикацией

Проводит Ольга на локальном сайте после финального серверного прогона.
Production не использовать. Проверять только свои одноразовые тестовые данные.

## Удаление аккаунта

1. В локальной админке выписать ID своих аккаунтов, которые нужно защитить.
   В `server/.env` задать `ADMIN_PROTECTED_USER_IDS` этими ID через запятую
   и перезапустить локальный backend. Пока параметр пуст, удаление выключено.
2. В карточке защищённого аккаунта убедиться, что удалить его нельзя.
   Аналогично проверить аккаунт с любой существующей записью платежа.
   Новую оплату для проверки создавать не нужно.
3. Открыть карточку одноразового аккаунта без платежей. Нажать удаление,
   отменить; затем ввести неправильный ID. Аккаунт должен остаться.
4. Подтвердить правильным ID. Карточка закрывается, аккаунт исчезает из списка.
   Если файлы ещё очищаются, дождаться сообщения о завершении или нажать повтор.
5. В старом пользовательском окне обновить страницу: прежний аккаунт потерял
   доступ. Повторный вход создаёт новый аккаунт с пустым архивом.

## Гостевой документ

1. В отдельном браузерном профиле без входа загрузить свою тестовую картинку.
   Проверить открытие фото и текста, обновление страницы и сохранение результата.
2. Войти из карточки результата: должен открыться тот же документ в личном
   архиве, с фото и прежними вариантами текста; дубликата быть не должно.
3. В другом профиле без гостевой cookie открыть ссылку на гостевое фото:
   изображение не должно быть доступно.
4. После переноса выйти из аккаунта в том же браузере и открыть прежнюю
   гостевую ссылку: фото и текст личного архива должны быть закрыты. Вход
   в другой аккаунт тоже не даёт доступа к этому документу.
5. Проверить окно удаления на телефоне или узкой ширине браузера:
   текст, поле ID и кнопки видны, горизонтальной прокрутки нет.

Распознавание своей картинки использует подключённый OCR/LLM и локальный
лимит; этот шаг Ольга выполняет сама. Границу десяти суток и аварийную очистку
проверяют автоматические тесты с искусственными данными: менять даты реальных
документов и запускать очистку существующих данных для ручной проверки не нужно.
