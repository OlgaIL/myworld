# Публикация исправления источника и ClientID после входа

Публикацию и проверку рабочего сайта выполняет Ольга.

## Изменение

Первый размеченный источник сохраняется в браузере при следующих переходах.
При входе по почте, Google, Яндексу и VK проверенные метки и ClientID переходят
в новую сессию Passport и сохраняются у пользователя. Перенос гостевого
документа в личный архив сохраняет прежнее поведение. Старые потерянные
источники автоматически не восстанавливаются.

Локальная независимая проверка 10 октября: 5/5 серверных тестов входа,
64/64 клиентских, 65/65 гостевого хранения/удаления аккаунтов; сборка клиента
и lint analytics.js прошли. Email и OAuth в тестах имитируются локально,
без запросов к внешним почтовым/OAuth/LLM сервисам.

В публикации также обновлены инструкции гостевого хранения: очистка раз
в сутки в 05:00, текущая проверка БД через `/api/monitor/health`.
Ольга уже перенесла накопленные файлы, очистила 1160 просроченных гостевых
документов и три записи с отсутствующими файлами, установила ежедневный cron
и подтвердила работу службы cron. Эти операции повторять для исправления
атрибуции не требуется. 35 исторических claimed-записей и 7 неизвестных файлов
сохранены для отдельного разбора.

Изменения OCR/тестировщика и новый блок админки «Гости и очистка» в runtime
этой публикации не входят. Новые зависимости, миграции и настройки `.env`
не требуются.

## Команды на сервере

1. Проверить ветку и рабочую папку:

```bash
cd /root/myworld
git status --short --branch
```

Должна быть `main`, без локальных изменений. Если вывод иной, сначала
разобрать его; не сбрасывать рабочую папку и не перезаписывать `.env`.

2. Обновить код, собрать клиент и перезапустить backend:

```bash
git pull --ff-only origin main
npm run build --prefix client && pm2 restart myworld-server --update-env
```

Отдельно останавливать backend не нужно. Его перезапуск кратковременно
прерывает доступ; успешная проверка БД при старте запускает фоновые workers
удаления аккаунтов и Telegram, которые пропускаются при ошибке старта БД.
При ошибке pull не продолжать к сборке. При ошибке сборки backend не перезапускается.

3. Через несколько секунд проверить новое состояние:

```bash
curl --fail --silent --show-error -w '\n' https://word2you.ru/api/health
curl --fail --silent --show-error -w '\n' https://word2you.ru/api/monitor/health
```

В первом ответе после нового старта должны быть `database.connected: true`
и новое `checkedAt`. Второй ответ должен быть `{"status":"ok"}`.
`/api/health` хранит результат проверки при старте; `/api/monitor/health`
проверяет актуальный доступ к БД с кэшем на 10 секунд.

При ошибке получить диагностический вывод:

```bash
pm2 logs myworld-server --lines 50 --nostream
```

4. Завершить контроль ранее выполненного гостевого перехода, только чтение:

```bash
cd /root/myworld/server
node scripts/transitionGuestStorage.js --dry-run 2>&1 | grep -E '"code"|"planned"'
node scripts/cleanupGuests.js --dry-run 2>&1 | grep -E '"code"|"candidates"'
```

У перехода ожидаются `planned: 0`, `busy: 0`, `errors: 0` и сохранённые
`orphanClaims: 35`, `orphanLegacy: 7`. У очистки — `legacy: 0`, `errors: 0`.
Новые просроченные кандидаты могут ожидать следующего ежедневного запуска;
их наличие само по себе не означает сбой. Не запускать повторный переход
`--apply` только ради публикации исправления атрибуции.

## Проверка атрибуции Ольгой

В новом приватном окне открыть:

```text
https://word2you.ru/photo-to-text?utm_source=manual_test&utm_campaign=check_A&utm_content=ad_A
```

Затем в том же окне перейти на:

```text
https://word2you.ru/photo-to-text?utm_source=manual_test&utm_campaign=check_B&utm_content=ad_B
```

Загрузить один тестовый документ и войти новым тестовым аккаунтом по почте
или через доступный OAuth-провайдер. Проверка реального распознавания
расходует обычный лимит/API и выполняется только Ольгой.

В админке у нового аккаунта проверить источник `manual_test`, кампанию
`check_A`, объявление `ad_A` и ClientID, если он получен от Метрики.
ClientID не должен теряться именно в момент входа; его отсутствие до входа
не компенсируется выдуманным значением. В личном архиве должен остаться
перенесённый гостевой документ с фото и текстом.

Повторный вход не должен заменять сохранённый источник или ClientID.
Старый аккаунт для этой проверки не подходит: его ранее сохранённая первая
атрибуция намеренно сохраняется. Директ остаётся остановленным до отдельного
решения Ольги после проверки.
