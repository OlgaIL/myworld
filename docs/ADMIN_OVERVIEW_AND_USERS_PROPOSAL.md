## 1. «Гости и очистка» на вкладке «Обзор»

Состав блока уже согласован Ольгой:

- Гостевые загрузки, успешная обработка и ошибки за выбранный период.
- Хранится сейчас гостевых документов; отдельно просроченные, ожидающие очистки.
- Удалённые гостевые документы и файлы за период — два отдельных показателя.
- Последний запуск очистки: время, результат, число удалений и ошибки.
- Ожидаемое расписание: ежедневно в 05:00 с указанием часового пояса cron.
- Предупреждение о пропущенном, прерванном или неуспешном запуске.

Периоды: 24 часа, 48 часов, 7 и 30 дней. Предложение: общий переключатель
для этого блока и статистики LLM, чтобы показатели относились к одному периоду.
Текущее хранение и очередь очистки показывают состояние сейчас, независимо
от выбранного периода. Нулевое число удалений при успешном запуске — норма.

Данные для отчёта сохранять отдельно от гостевого содержимого. Удаление или
перенос документа не должны стирать историю загрузок. Считать документы
и принятые загрузки, а не вызовы LLM. Повторная загрузка файла в существующий
гостевой документ — новая загрузка, а не новый аккаунт. Удаление гостевой
строки при переносе в ЛК не считать очисткой по сроку хранения.

В отчёте о файлах различать фактическое удаление и уже отсутствующий файл.
Повторный запуск не должен повторно увеличивать счётчики. Успех показывать
после завершения операции, а не только по старту или нулевому числу ошибок
при пропуске из-за блокировки. Ошибка API не должна отображаться как нули.

Надёжной истории до внедрения счётчиков нет: показывать начало сбора данных,
не восстанавливать прошлые числа приблизительно и не переносить вручную
1160 удалений в новую статистику без отдельного решения об импорте.
35 исторических claimed-записей и 7 неизвестных файлов остаются исключениями
для ручного разбора; не смешивать их с обычной очередью просроченных гостей.

## 2. Список пользователей на всю ширину

Предложение для согласования:

- Короткие строки: email/имя и ID, регистрация, успешные покупки,
  остаток обработок, число документов, дата последней обработки.
- Детальные данные, ClientID/Вебвизор, источник, устройства, настройки
  лимитов и удаление аккаунта — внутри подробной карточки.
- Поиск по email, имени и ID. Email искать без учёта регистра и по части строки.
- Фильтры можно сочетать; показывать число найденных пользователей и сброс.
- Загружать по 25 пользователей, с переходами между страницами.
- Сортировки: новые первыми (по умолчанию), последняя обработка,
  количество документов.

Первая версия фильтров:

1. Оплаты: все / есть успешная покупка / нет успешных покупок.
2. Регистрация: сегодня / 7 дней / 30 дней / произвольный диапазон дат.
3. Использование: обрабатывали документы за 7 дней / за 30 дней /
   ещё не обрабатывали. Это не история посещений сайта.
4. Дополнительный фильтр по наличию остатка обработок — обсудить с Ольгой.

Фильтры источника и устройства можно добавить позже по необходимости.
Ручное начисление и платёж со статусом failed/pending не означают успешную
покупку. Защита удаления по любой платёжной записи и ADMIN_PROTECTED_USER_IDS
продолжает действовать независимо от классификации в фильтре «Оплаты».

Данные для общего обзора не считать по текущей странице или отфильтрованному
списку. Общее число пользователей/документов получать отдельно. Поиск,
фильтры, сортировка и страницы применяются на сервере; данные Метрики
для списка запрашиваются только для отображаемых пользователей.

## 3. Подробности пользователя: выбрана панель справа

Ольга выбрала выдвижную панель справа. Сравнение рассмотренных вариантов:

| Вариант | Поведение | Особенности |
| --- | --- | --- |
| Панель справа, рекомендуемый | Карточка выдвигается поверх правой части списка | Сохраняется контекст списка; удобно переключать пользователей |
| Большой попап | Карточка открывается в центре поверх затемнённого списка | Хорошо выделяет одного пользователя; большая карточка прокручивается |
| Отдельная страница | Самостоятельный адрес пользователя | Удобны прямые ссылки и длинная история; нужен возврат к списку |

Для панели и попапа на телефоне — карточка на весь экран. После закрытия
возвращаться к прежнему поиску, фильтрам, странице и позиции списка.
Сохранение изменений обновляет соответствующую строку, а удаление убирает её
и корректирует число найденных пользователей. Предусмотреть загрузку,
ошибку загрузки, отсутствие пользователя, клавиатуру и возврат фокуса.
Несохранённые изменения не терять при закрытии или смене пользователя.
Вложенное подтверждение удаления не должно одновременно закрывать карточку.
