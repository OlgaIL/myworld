# Список пользователей — локальная приёмка и публикация

22 октября 2026. По поручению Ольги реализован этап 2 админки.

## Что изменилось

Список пользователей занимает всю ширину, по 25 пользователей на странице.
Поиск по email/имени без регистра и по числовому ID, фильтры успешных покупок,
регистрации и последней обработки; сортировка по регистрации, обработке или
числу хранимых документов. При изменении фильтра показывается первая страница.
При удалении последней строки на странице сервер возвращает предыдущую.

Служебная подпись уменьшена до 12 px. В строки возвращены компактные сведения:
источник и фраза, устройство, вход, визиты, лимиты, статистика и история документов,
ClientID с копированием и Вебвизором. Регистрации сегодня по Стамбулу подсвечены
голубым, успешные покупатели — зелёным. При совпадении остаётся зелёный фон
и метка «Сегодня»; ручные начисления не дают платную подсветку.

Покупкой считается только `payments.status = succeeded`. Подарки, ручные квоты
и незавершённые платежи не дают отметку покупки. Даты регистрации — календарные
дни Europe/Istanbul: сегодня, последние 7/30 дней с сегодняшним включительно,
произвольный диапазон с включённой конечной датой. Фильтр обработки — последние
7/30 суток по `last_processing_at`; «ещё не обрабатывали» учитывает и накопительный
`records_processed_total`. Текущий архив не заменяет историю обработок.

`GET /admin-api/users` теперь возвращает `{users,total,page,pageSize,timeZone}`.
Все внутренние потребители обновлены. Параметры проверяются и передаются в SQL
отдельно от текста запроса. Сортировки заданы белым списком с дополнительным ID.
Счётчики обзора получает отдельный `/admin-api/users-summary`, без фильтров;
визиты Метрики запрашиваются только для текущей страницы или карточки.

Карточка открывается справа в модальном диалоге, на телефоне — во весь экран.
Escape/кнопка закрытия возвращают в список, сохраняют фильтры, страницу, фокус
и прокрутку. Несохранённая форма запрашивает подтверждение закрытия; во время
сохранения карточка не закрывается. Удаление имеет прежний отдельный диалог:
его отмена сохраняет карточку, успех обновляет список и общие показатели.
Ошибки поиска, исчезнувший пользователь и повтор загрузки показываются отдельно.

Сохранены начисления, улучшения, защита удаления оплаченных/служебных аккаунтов,
CSRF и исключение админки из аналитики. OCR reviewer и его приватный набор —
отдельная работа; его изменения в общих файлах сохранены.

## Локальные проверки

```powershell
Set-Location C:\Users\olgak\PROJECTS\myworld
npm run test:admin-users --prefix server
npm test --prefix client
```

Для lint запускать из папки client, где находится конфигурация:

```powershell
Set-Location C:\Users\olgak\PROJECTS\myworld\client
node node_modules/eslint/bin/eslint.js src/pages/AdminPage.jsx src/components/AdminUsersTable.jsx src/components/AdminUserDrawer.jsx src/utils/adminUsers.js src/services/adminApi.js tests/adminUsers.test.js
$env:VITE_CLARITY_ENABLED='true'
$env:VITE_CLARITY_HOSTS='word2you.ru'
npm run build
```

`test:admin-users` создаёт отдельные искусственные схемы локального PostgreSQL,
проверяет localhost до подключения и удаляет только собственные тестовые схемы.
Реальные пользователи и загрузки не изменяются. Проверены **26 серверных тестов**
(поиск, сочетания фильтров, даты, страницы, API/авторизация, существующая аналитика,
защита удаления и очистка), **97 клиентских**, lint и сборка с пререндером.
Предупреждения baseline-browser-mapping и о размере JS-чанка были и раньше.

В отдельном фоновом Edge проверены 1280/375 px, длинный email, поиск и запоздавший
ответ, страницы и неизменность общих чисел, закрытие/отмена несохранённого,
сохранение, фокус, вложенное удаление и обновление после него. API в этих
браузерных проверках подменены; внешние запросы блокировались. Это отдельный
браузер, не управление открытыми окнами Ольги. Превью — work/admin-users-*.png;
эти файлы и тестовый harness не публиковать.

Повторно проверены компактные сведения в списке, копирование ClientID без
открытия карточки, размер подписи, обе подсветки и их сочетание. Отдельный
клиентский тест проверяет смену календарного дня по Стамбулу.
Обе части строки пользователя открывают карточку и подсвечиваются вместе
при наведении. Проверено нажатие на мелкие сведения; копирование ClientID
сохраняет самостоятельное действие без открытия карточки.

Дополнительно настоящий локальный backend на 4000 проверен через собственную
HTTP-сессию администратора: summary, страницы/сортировка, покупки, карточка,
no-store. Сессия завершена. Пользовательские данные не менялись.
Backend перезапущен с новым кодом; существующие локальные сессии требуют входа.

Для приёмки Ольге: открыть `http://localhost:5173/admin-control`, войти и выбрать
«Пользователи». Проверить свои варианты поиска/фильтров и карточку.
Никаких новых обработок OCR или платных API при проверках агент не запускал.

После отдельного коммита локально:

```powershell
Set-Location C:\Users\olgak\PROJECTS\myworld
git push origin main
```

На сервере проверить чистоту рабочей папки:

```bash
cd /root/myworld
git status --short
```

Если есть изменения — остановиться и сохранить их. При чистой папке:

```bash
cd /root/myworld &&
git pull --ff-only origin main &&
VITE_CLARITY_ENABLED=true VITE_CLARITY_HOSTS=word2you.ru npm run build --prefix client &&
pm2 restart myworld-server --update-env &&
git log -1 --oneline
```

**Миграции БД, новые зависимости и изменение env не нужны.** Установка npm
зависимостей для этого этапа не требуется. Изменение формата API требует
обновить и клиент, и backend. После рестарта нужно заново войти в админку.

Команды проверки Ольгой:

```bash
pm2 status myworld-server
curl --fail --silent --show-error https://word2you.ru/api/health
curl --silent --output /dev/null --write-out '%{http_code}\n' https://word2you.ru/admin-api/users
curl --silent --output /dev/null --write-out '%{http_code}\n' https://word2you.ru/admin-api/users-summary
```

Без административной сессии последние два запроса должны вернуть 401.
После входа проверить поиск, фильтры, числа обзора, страницы и карточку на
компьютере и телефоне. Production агент не обновляет и не проверяет.
