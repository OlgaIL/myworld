# ТЗ и промпт: хранение гостевых документов

Согласовано с Ольгой 7 октября 2026 года. Модель ещё ожидает согласования.

## Результат

Гость может открыть фото и результаты обработки в том же браузере в течение
10 суток после загрузки каждого документа. После этого доступ закрывается,
а данные удаляются регулярной очисткой. После входа документ становится
документом личного кабинета и не подлежит гостевой очистке.

## Промпт для разработческой ветки

Реализуй хранение и очистку гостевых документов Word2you по этому ТЗ.
Работай только в `C:\Users\olgak\PROJECTS\myworld`. Прочитай `AGENTS.md`,
`docs/ROADMAP.md` и этот файл. Не создавай worktree, копии проекта или новые
серверы. Не публикуй и не тестируй production. Не вызывай платные OCR/LLM API.
Не запускай других агентов и не меняй модель без согласования с Ольгой.

Сначала проверь `git status --short --branch` и staged diff. В основной папке
есть незакоммиченные изменения OCR/LLM, тестировщика и документации: сохрани
их и не включай в свою работу. Не используй reset/stash и не переключай ветку
при неоднозначном состоянии. Данная разработческая ветка — отдельный чат,
работающий последовательно в той же папке. Коммит и push оставь принимающему
агенту; представь ему точный список файлов и дифф своего изменения.

### 1. Срок хранения и доступ

- Установи гостевой срок 240 часов от загрузки каждого документа. Обычный
  просмотр, повторная обработка и исправление текста не продлевают этот срок.
- Согласуй значение по умолчанию и конфигурацию. Учти возможное существующее
  значение 24 часа в `.env`; не показывай секреты и не меняй боевой `.env`.
- Продли гостевую cookie так, чтобы новые документы были доступны весь свой
  срок: при новой загрузке обновляй cookie как минимум до срока последнего
  документа. Не продлевай срок документов при обновлении cookie.
- Сохрани проверку принадлежности документа гостевой сессии для текста и файла.
  После истечения срока данные не выдаются независимо от запуска очистки.

### 2. Раздельное хранение

- Фото гостей храни в `server/uploads/guests/`, фото личного кабинета —
  в `server/uploads/users/`. Тексты остаются в отдельных таблицах PostgreSQL:
  `guest_documents` и `photos`.
- Сохрани работу загрузки, просмотра, обработки и повторной обработки.
  Каталоги не публикуй через открытый static endpoint.
- При входе перенеси файл и все результаты обработки в личный архив.
  Сначала создай устойчивую копию файла в пользовательском каталоге, затем
  зафиксируй перенос в БД, и только после успешной фиксации убирай гостевой
  оригинал и гостевую запись. Конечный результат — один документ в ЛК.
- Обеспечь повторяемость переноса: одновременные запросы и сбой на любом этапе
  не создают второй документ и не теряют файл. Используй блокировки/транзакцию
  и устойчивое состояние переноса; сетевые OCR/LLM вызовы не держи внутри
  долгой транзакции. Гостевая очистка не должна конфликтовать с переносом.
- Проверь ссылки на гостевые записи, заявки на улучшение и счётчик документов,
  перенесённых из гостевого режима. Сохрани необходимые связи/метаданные без
  сохранения второй копии гостевого текста.

### 3. Переход существующих данных

- Подготовь отдельный безопасный скрипт с dry-run для старых файлов из общей
  папки `uploads`, включая файлы, на которые ссылаются обе таблицы.
- На dry-run покажи только ID, относительные пути, количество и план действий;
  не печатай тексты, email, токены или содержимое `.env`.
- При переносе существующих документов срок считай от исходной загрузки,
  а не от запуска миграции. Не выдавай всем ещё десять дней с момента публикации.
- Предусмотри повторный запуск и прерывание. Не удаляй общий файл, пока у него
  остаются ссылки. Гостевая очистка работает только внутри гостевого каталога;
  старые общие файлы обрабатывает скрипт перехода.
- Первое изменение/удаление накопленных production-данных выполняет Ольга
  после просмотра dry-run. Локально используй только искусственные данные.

### 4. Очистка

- Подготовь CLI для запуска раз в час через существующий серверный планировщик.
  Удали фото, тексты и результаты просроченных гостей небольшими порциями.
- Исключи конкурирующие запуски, активный перенос и активную обработку; после
  их завершения просроченный документ должен стать кандидатом следующего запуска.
  Предусмотри восстановление после зависшего/оборванного процесса.
- Удаление файла и строки БД согласуй так, чтобы ошибка файловой системы
  оставляла возможность повторить очистку. Отсутствующий файл не ломает повтор.
- Не следуй произвольным путям из БД за пределы гостевого каталога; защити
  обход пути и выход через симлинк. Не используй рекурсивное удаление каталогов.
- Журналируй итоговые количества и технические ошибки без содержимого документов.
- Добавь dry-run. Старые пустые гостевые сессии пока не удаляй: срок не согласован.

### 5. Бэкапы и границы задачи

- Проверь совместимость новой структуры с существующим backup/restore:
  обе вложенные папки должны попадать в копию и корректно восстанавливаться.
- Не меняй срок хранения бэкапов и настройки S3. Документируй, что удалённые
  данные остаются в старых копиях до истечения срока хранения этих копий.
- Подготовь команду очистки просроченных гостевых данных после восстановления
  и до открытия приложения пользователям.
- Не реализуй в этой задаче удаление аккаунтов, Telegram для бэкапа или очистку
  личных архивов. Для личных архивов согласовано отдельное будущее правило:
  год неактивности, предварительное email-предупреждение и время на сохранение;
  для покупавших пакеты — если пакет исчерпан. Детали предупреждения ещё не заданы.

### Критерии приёмки

Проверь локально на искусственных документах и файлах:

1. Документ доступен до границы 240 часов и недоступен после неё.
2. Загрузка нового документа не продлевает срок старого; cookie не истекает
   раньше нового документа. Чужая сессия не получает файл или текст.
3. Очистка удаляет просроченные гостевые файл и содержимое БД; непросроченные
   и пользовательские документы сохраняются. Dry-run ничего не изменяет.
4. Вход переносит файл и все варианты текста в ЛК, убирает гостевые оригиналы;
   последующая гостевая очистка не затрагивает архив и не ломает счётчик переноса.
5. Повторный/одновременный вход не создаёт дубль. Сбой копирования, фиксации БД
   или удаления оригинала допускает безопасный повтор без потери документа.
6. Очистка, обработка и перенос не удаляют данные друг друга. Два запуска
   очистки одновременно не приводят к ошибочному удалению.
7. Скрипт перехода сохраняет старые общие файлы до завершения переноса всех
   ссылок; повторный запуск безопасен, исходная дата загрузки сохраняется.
8. Отсутствующий файл и ошибка доступа не останавливают весь пакет очистки;
   пути за пределами гостевого каталога не удаляются.
9. Бэкап/восстановление включают вложенные папки. Просроченные восстановленные
   данные можно очистить до открытия сайта.

### Отчёт принимающему агенту

Верни описание окончательной схемы, перечень своих файлов, результаты проверок,
оставшиеся ограничения и точные команды для Ольги: обновление кода, настройка
240 часов, миграции, dry-run/переход данных, установка расписания, перезапуск,
проверка production и восстановление при ошибке. Обнови ROADMAP, не отмечая
проверку production выполненной. Не считай задачу законченной без локальной
проверки переноса и очистки при сбоях.
