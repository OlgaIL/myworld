# Мониторинг Word2you

## Доступность

Внешний HTTP-монитор проверяет `https://word2you.ru/api/monitor/health`.
Ответ `200 {"status":"ok"}` означает, что сервер отвечает и проверка PostgreSQL
успешна; при ошибке БД возвращается `503`. Проверка не вызывает OCR или LLM.
Результат проверки БД кэшируется на 10 секунд, чтобы публичный endpoint не
создавал новый запрос к БД при каждом обращении.
Проверять также главную страницу, чтобы заметить ошибки Nginx и выдачи сайта.
Настроить уведомление после нескольких подряд неудачных проверок и отдельное
уведомление о восстановлении. Аккаунт мониторинга и адресаты задаются вручную.

## Обработка LLM

Админка показывает агрегаты из `llm_attempt_events` за 24/48 часов, 7/30 дней.
Это число вызовов модели, а не документов. Внешний HTTP-монитор не обнаружит
таймауты LLM, пока сайт продолжает отвечать. Порог автоматической тревоги
согласовать после недели наблюдения, чтобы единичная ошибка не создавала шум.
Содержимое документов и персональные данные не передавать мониторингу.

## Резервная копия

Скрипт `scripts/backup-production.sh` поддерживает необязательную переменную
`BACKUP_HEARTBEAT_URL`. Если она задана, запрос отправляется только после
успешного создания копий и загрузки в S3. URL содержит секретный токен:
хранить его вне Git и не выводить в лог. Внешний heartbeat ожидает один сигнал
после каждого ночного запуска и сообщает об отсутствии сигнала. Если URL не
задан, резервное копирование работает по-прежнему.

Проверить настройку мониторинга на тестовом адресе и тестовом heartbeat до
изменения production cron. Не публиковать токены в скриншотах или документах.
