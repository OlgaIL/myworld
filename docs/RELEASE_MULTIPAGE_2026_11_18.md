# Многостраничные документы — 18 ноября 2026

Авторизованные пользователи могут загружать до 25 фото в один документ,
добавлять новые страницы или одностраничные записи из архива, менять порядок,
выделять страницы и разделять документ. Одна новая фотография — одна обработка;
операции с готовыми страницами бесплатны. Недостаточный баланс блокирует весь
выбор до запуска. Гостевая пакетная загрузка по-прежнему недоступна.

Шапка следует текущей первой странице. Страницы имеют свои вкладки и статусы;
горизонтальная навигация остаётся видна при прокрутке. «Скопировать всё» собирает
открытые вкладки по порядку, с подтверждением и галочкой после успеха.
При добавлении видны статус и новая страница. Отметка «Добавлена из архива»
сохраняется отдельно от результата распознавания, включая объединение из списка.
Диалоги используют общий блок действий с линией и широкими кнопками.

## Миграции

- `049_multipage_documents.sql`: контейнеры, страницы, старые ссылки,
  идемпотентные операции и загрузочные сессии. Прежние фото и результаты сохраняются.
- `050_document_page_archive_origin.sql`: происхождение страниц из архива;
  восстановление отметок прежних объединений по квитанциям операций.

Обе применены локально после резервных копий. Миграция 050 проверила неизменность
пользователей, фотографий, гостевых записей и сохранённых результатов.

Исправление 18 ноября: при совместном запуске 049/050 через `db:migrate`
отложенные проверки после заполнения document_pages мешали ALTER TABLE в 050.
Теперь 050 выполняет накопленные проверки перед изменением таблицы и возвращает
отложенный режим. Ошибка воспроизведена на временной локальной схеме до правки;
после неё 36 проверок прошли. Тест применяет обе миграции одной транзакцией,
как рабочий migration runner, с уже существующими фотографиями.
Неудачный пакет целиком откатывается; вручную менять schema_migrations не нужно.

## Проверка

Проверены сборка клиента и SSR, клиентские проверки, 103 серверные проверки
общего набора и затем 36 профильных проверок с миграцией 050. Проверки БД
используют временные локальные схемы и не вызывают платное распознавание.
Через Browser Plugin проверены desktop/mobile, выбор страниц, диалоги,
копирование, учебные загрузки, добавление из архива, разделение и выделение.
Пользовательская проверка всей функции продолжается.

## Публикация Ольгой

Перед обновлением сохранить свежую резервную копию БД и файлов обычным способом.
Команды на сервере после SSH:

```bash
cd /root/myworld
git pull
cd server
npm ci
npm run db:migrate
cd ../client
npm ci
npm run build
pm2 restart myworld-server
curl -fsS http://127.0.0.1:4000/api/health
```

Проверить архив, старую ссылку документа, сборку двух готовых страниц,
две отметки «Текст загружен»/«Добавлена из архива», перестановку первой страницы
и копирование. Объединение не должно менять баланс. Боевой сервер агент не меняет.

Откат только приложения после 049 ограничен: старый клиент не отображает
контейнеры. При необходимости полного отката согласовать восстановление свежей
резервной копии; не удалять новые таблицы или страницы вручную.
