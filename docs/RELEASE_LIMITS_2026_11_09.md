# Общие публичные лимиты и пять обработок новым пользователям

Решение Ольги 9 ноября: гости — 3; новые регистрации — 5 бесплатных обработок.
Лимиты и остатки существующих аккаунтов сохраняются. Впоследствии должно быть
возможно вернуть 10 без редактирования всех текстов.

## Источники и тексты

- Гости: GUEST_DOCUMENT_LIMIT из server/.env. На локалке установлено 3.
- Новые пользователи: DEFAULT столбца users.free_processing_limit в БД.
  Миграция 048 меняет только DEFAULT на 5, не выполняя UPDATE пользователей.
- GET /api/public-limits возвращает только эти два числа без авторизации,
  без создания сессии и без кеширования. Значение из БД читается при запросе.
- Главная, «О проекте», рукописный лендинг, CTA после результата и его аналитика
  используют общий клиентский контекст. Обновление — при открытии страницы и
  возврате фокуса. Старые данные гостевого счётчика не переопределяют свежий лимит.
- При отсутствии данных показывается текст без количества. В статическом HTML
  и SEO нет фиксированного обещания; после загрузки клиент подставляет реальное
  количество в надписи и описание главной страницы.
- Личные лимиты, подарки, платные пакеты и списания продолжают браться из аккаунта.

## Локальная проверка

048 применена только к localhost. Проверены новый INSERT с лимитом 5 и точная
сохранность лимитов/счётчиков трёх прежних аккаунтов; пробная запись откатана.
37 штатных серверных проверок прошли во временной схеме, включая бесплатные,
подарочные и платные обработки. Ещё 3 проверки public-limits и 23 клиентских
проверки прошли. React SSR проверяет актуальные 3/5, будущие 7/10 и отсутствие
выдуманных чисел при сбое. ESLint и сборка прошли.
Browser Plugin на настоящем localhost подтвердил 3/5 на главной, «О проекте»
и рукописном лендинге, а также актуальное описание главной страницы.
Backend и Vite запущены локально. Платных запросов, production-действий нет.
Коммит/публикация этой правки впереди.

## Будущая смена количества

Для гостей изменить GUEST_DOCUMENT_LIMIT в server/.env и перезапустить backend.
Для новых регистраций изменить только DEFAULT, например для возврата на 10:

```sql
ALTER TABLE users ALTER COLUMN free_processing_limit SET DEFAULT 10;
```

Это не изменяет лимиты существующих аккаунтов. Тексты подхватят число после
обновления страницы/возврата фокуса; пересборка клиента для дальнейших смен не нужна.

## Выпуск текущего изменения

Впервые нужны новая миграция 048, сборка клиента и перезапуск backend.
Ольга выполняет публикацию и production-проверку сама, команды — в чате по одной.
Для выполнения после получения коммита на сервере:

```bash
cd /root/myworld/server && npm run db:migrate
```

После подтверждения миграции отдельно — обычная сборка клиента и рестарт:
`cd /root/myworld/client && npm run build`, затем `pm2 restart myworld-server`.
Inspectlet env повторять не нужно. Проверка Ольгой:
`curl --fail --silent --show-error http://127.0.0.1:4000/api/public-limits` — 3/5,
обновить публичные страницы и проверить сохранённый лимит старого аккаунта.
При публикации через день или позже новый default действует с применения миграции,
не задним числом. Уже существующие на этот момент аккаунты не урезаются.

Откат DEFAULT на 10 — SQL выше; не выполнять массовый UPDATE. Отмена кода и
сборка старого клиента не должны переписывать сохранённые персональные лимиты.
