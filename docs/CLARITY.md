# Microsoft Clarity: запись визитов

Проект: `yy89cpbeew`. Основной домен: `word2you.ru`. Зеркала сейчас не подключены.
Публикацию и проверку рабочего сайта выполняет только Ольга.

## Поведение

**Изменение от 23 октября 2026:** по запросу Ольги содержимое документов
открывается для записи. Ниже описан новый режим; до его публикации на сайте
сохраняется прежнее маскирование. Изменение не раскрывает старые записи.

- Стандартная запись после отдельного согласия «Разрешить запись».
  Новое согласие явно включает передачу Microsoft фото и текста, в том числе
  возможных личных данных в документах. Ключ `word2you_clarity_consent_v2_documents`:
  старое согласие v1 на маскированную запись не запускает новый режим.
  Метрика сохранена.
- Отказ «Без записи визитов» полностью исключает загрузку Clarity.
  Выбор можно изменить на странице политики; отзыв останавливает запись и
  перезагружает страницу. Отзыв в другой вкладке также применяется.
- Вызов consentv2 разрешает analytics_Storage и запрещает ad_Storage.
  Собственные метки, события, user ID и связь с диагностикой не добавлены.
- Скрипт вставляется один раз на документ; обычные SPA-переходы его не вставляют повторно.
- Фотографии документов, текст, таблицы, исправления, названия, описания,
  категории/теги и архивная навигация имеют `data-clarity-unmask="true"`.
  Содержимое этих областей передаётся в записи без маскирования.
  Имя, аватар и почта учётной записи, поля входа и коды по-прежнему скрыты.
  Почта или другие личные данные **внутри документа** не скрываются выборочно.
  Публичные кнопки, подсказки, ожидание и стандартные ошибки доступны в записи.
  Подробности ошибок обработки из серверных данных маскируются отдельно.
- Админка исключена. Переход в неё из записываемого приложения останавливает
  SDK и открывает новый документ; админский интерфейс не монтируется в старый.
- Допускаются только известные страницы и серверные идентификаторы документов
  (числовой ID гостя либо сгенерированное имя timestamp+UUID). Названия из OCR
  и исходное имя загруженного пользователем файла в URL не добавляются.
- Консервативное ограничение: страницы с query/hash и произвольными путями,
  включая старые имена файлов, не записываются. В частности, вход с UTM-параметрами
  не запускает Clarity в этом документе. Подробный referrer с неизвестным путём
  или параметрами также исключает запись; внешний referrer только с origin допускается.
  Это защита URL от передачи почты, кодов и названий. Метрика продолжает работать.
- В dev и на localhost Clarity выключен. Ошибка загрузки/CSP/блокировщик
  не блокируют приложение. При отказе storage запуск закрыт.

## Настройки и отключение

Переменные **сборки клиента**, не `server/.env`:

```dotenv
VITE_CLARITY_ENABLED=true
VITE_CLARITY_HOSTS=word2you.ru
```

По умолчанию действуют эти значения. `VITE_CLARITY_ENABLED=false` при сборке
полностью выключает счётчик. Для зеркала потребуется явно согласованный домен
в списке через запятую и повторная сборка. Не добавлять localhost в боевую сборку.

В кабинете Clarity Ольге проверить Settings → Setup/Consent: получение согласия;
Settings → Masking: Balanced. Документы открываются явными атрибутами unmask;
глобально выбирать Relaxed не требуется. Не добавлять unmask для профиля и входа.
Фото с авторизованным URL или `blob:` могут не воспроизводиться: запись адреса
изображения не равна сохранению его пикселей. Публичный доступ к пользовательским
файлам ради записи не открывается; реальную видимость фото проверяет Ольга.
Источники: [маскирование Microsoft](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-masking),
[Consent API V2](https://learn.microsoft.com/en-us/clarity/setup-and-installation/clarity-consent-api-v2).

## Публикация Ольгой

Текущая публикация от 23 октября включает новый режим записи документов и новое
согласие v2, описанные выше. Публикация 16 октября с маскированием документов
сохранена как история в `docs/DEPLOY_PHOTO_TEXT_EXAMPLE.md`; её описание масок
не относится к новому режиму. Чистые URL промостраниц разрешены, UTM/query/hash
по-прежнему исключены; админка, профиль и коды входа остаются защищёнными.

Сначала доставить согласованные изменения этой задачи в `origin/main` обычным
процессом проекта. Не включать чужие незавершённые изменения через `git add .`.
Команды ниже получать и запускать только после этого. Если pull сообщает конфликт
или рабочие изменения — остановиться и сохранить их.

Подключение с компьютера Ольги:

```powershell
ssh root@147.45.246.205
```

На сервере (после доставки согласованных изменений в origin/main):

```bash
cd /root/myworld
git status --short
git pull --ff-only origin main
VITE_CLARITY_ENABLED=true VITE_CLARITY_HOSTS=word2you.ru npm run build --prefix client
```

Миграций и новых зависимостей нет. PM2/backend и nginx перезапускать не нужно:
меняются статические файлы клиента. Для открытых вкладок нужна перезагрузка.
Имеющиеся вкладки со старой сборкой сохраняют прежнее поведение до перезагрузки.

Отключение для новых загрузок страниц:

```bash
cd /root/myworld
VITE_CLARITY_ENABLED=false VITE_CLARITY_HOSTS=word2you.ru npm run build --prefix client
```

Уже открытые вкладки не получают новый bundle автоматически. Пользователь
может немедленно остановить запись кнопкой в политике. Для общего немедленного
отключения проверить доступную остановку записи в кабинете Clarity.

## После публикации — подтвердить Ольге

1. В приватном окне открыть `https://word2you.ru/` без query/hash.
   До согласия и после отказа в Network нет запросов к `clarity.ms`.
   Старое согласие v1 не загружает SDK: появляется новый запрос с описанием
   передачи документов. Разрешить запись: один tag с ID `yy89cpbeew`,
   при переходах tag не дублируется.
2. Только искусственное фото: загрузка, ожидание, результат, повторная попытка.
   В другом тестовом визите заблокировать Clarity в DevTools: сайт работает.
3. Открыть проект Clarity → Recordings и найти тестовый визит по времени/страницам.
   Проверить видимость кнопок, ожидания, стандартных ошибок, фото, текста,
   заголовков, таблиц/исправлений и архива. Имя/почта учётной записи, код и аватар
   должны остаться скрытыми. Документы могут содержать личные данные, которые
   теперь передаются без маскирования. Запись может
   появиться с задержкой; настройки маскирования применяются к новым визитам.
4. Открыть админку напрямую и перейти в неё из пользовательского интерфейса:
   админские страницы/данные отсутствуют в Recordings. Отозвать согласие на
   `/privacy`: после перезагрузки нет Clarity; повторить во второй вкладке.
5. Подтвердить работу прежней Метрики, основного домена и фактическое получение
   записей с согласиями. Зеркало не проверять и не включать в этой задаче.

Эти production-проверки агент не выполнял. Задачу считать опубликованной только
после подтверждения Ольги; при обнаружении данных учётной записи или кодов
сразу выключить запись. Старые записи остаются маскированными.
