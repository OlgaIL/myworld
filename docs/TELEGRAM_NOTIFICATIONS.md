# Уведомления в Telegram

Используем два закрытых чата: `События` для сообщений без звука и
`Техника` для срочных тревог, включая ночные, и сообщений о восстановлении.
Платную подписку на мониторинг пока не подключаем.

## Чат «События»

Создайте бота через BotFather, добавьте его в закрытый чат `События` и
разрешите отправлять сообщения. Токен бота и ID чата храните только в
`server/.env`:

```dotenv
TELEGRAM_BOT_TOKEN=<токен бота>
TELEGRAM_EVENTS_CHAT_ID=<ID закрытого чата>
```

После сохранения токена в `server/.env` отправьте в чате команду
`/start@имя_бота`. Чтобы узнать ID чата, выполните локально:

```powershell
cd C:\Users\olgak\PROJECTS\myworld\server
node scripts/telegramChatIds.js
```

Команда покажет названия и ID чатов, не выводя токен. Добавьте нужный ID
в `TELEGRAM_EVENTS_CHAT_ID`. Перед перезапуском сервера примените миграцию
`032_notification_outbox.sql`; на локалке она уже применена 3 октября 2026 года.

При заданных токене и ID чата сервер отправляет из очереди новые регистрации,
подтверждённые оплаты ЮKassa и заявки на улучшение. Сообщения приходят без звука.
В сообщении об оплате есть внутренний номер платежа и напоминание отправить чек.
Также передаётся email аккаунта, если он известен. Текст и фото документов
в Telegram не отправляются.

Повторный webhook оплаты не создаёт новое уведомление. Если Telegram временно
недоступен, событие остаётся в очереди и отправляется повторно позднее. При сбое
между отправкой сообщения и записью результата в БД возможен редкий дубль:
перед повторной отправкой чека сверяйте номер платежа.

## Публикация чата «События»

6 октября Ольга сообщила, что бот подключён к локальному серверу.
Перед публикацией отдельно проверить получение регистрации, оплаты и заявки.

На сервере выполнить из основной папки проекта:

```bash
cd /root/myworld
git status --short --branch
git pull --ff-only origin main
nano server/.env
```

В `server/.env` добавить `TELEGRAM_BOT_TOKEN` и `TELEGRAM_EVENTS_CHAT_ID`
с теми же значениями, которые используются локально. Секреты не включать в Git.
Затем:

```bash
cd /root/myworld/server
npm run db:status
npm run db:migrate
npm run db:status
pm2 restart myworld-server --update-env
pm2 logs myworld-server --lines 50 --nostream
```

В статусе должна быть применена миграция `032_notification_outbox.sql`.
Если обновление кода или миграция завершились ошибкой, остановиться до перезапуска.
Изменений клиента и новых зависимостей в этой публикации нет.
Ольга проверяет на рабочем сайте регистрацию, заявку и следующую подтверждённую
оплату: каждое событие должно прийти в тихий чат. Повторный webhook оплаты
не должен создавать второе событие. Исторические события миграция не рассылает.

## Чат «Техника»

Собственную проверку нужно разместить вне сервера Word2you, чтобы она могла
сообщить и о полной остановке сервера. Предлагаемый вариант — небольшой
монитор на бесплатном тарифе Cloudflare Workers; подключение ещё не выполнено.

Монитор проверяет главную страницу и `/api/monitor/health`, который возвращает
код 503 при недоступной БД. После подтверждённого сбоя отправляет тревогу в
`Техника`, а после восстановления — отдельное сообщение. Повторять одну и ту
же тревогу при каждом опросе не нужно.

Скрипт бэкапа отправляет сигнал на `BACKUP_HEARTBEAT_URL` только после успешной
загрузки копии в S3. Монитор должен хранить время последнего сигнала и тревожить,
если ночная копия не подтверждена к согласованному сроку.

Результаты вызовов LLM уже записываются в `llm_attempt_events`. Порог тревоги и
период наблюдения согласуем после недели сбора данных. Единичный отказ не
должен вызывать срочное уведомление.

Миграция 032 не включает технические тревоги автоматически. При подключении
проверим звук чата на телефоне и работу уведомлений ночью. Токены и секреты
монитора храним вне Git.
