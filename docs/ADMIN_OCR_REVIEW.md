# Ручная проверка контрольных фотографий

Страница `/admin-control/ocr-check` открывается по ссылке из админки. Требуется
действующая административная сессия. При открытии она последовательно обрабатывает
9 контрольных фотографий в режиме бесплатного пользователя из текущих настроек.
Повторный запуск можно выполнить для гостевого, бесплатного или платного режима.
Это реальные обращения к выбранным OCR/LLM-провайдерам с их обычной стоимостью.

На каждой карточке — превью с увеличением и общий компонент сайта
`DocumentTextVariants`: обычный и исходный текст, оформление и таблицы, если
они обнаружены. Таблицы собираются отдельной кнопкой, как в обычном документе.
Можно повторить одну фотографию или остановить очередь после текущей.

Обработка использует `processingPipelineService`, восстановление таблиц —
`documentTableService`, выдача результата — общий `mapPhotoInfo`, как у обычной
карточки. Пользовательские документы и квоты не изменяются,
тестовые LLM-попытки не попадают в продуктовую статистику. Результаты хранятся
в памяти backend до 30 минут; перезапуск backend удаляет их. Обновление страницы
начинает новый прогон. Кнопки исправлений доступны для просмотра без сохранения.

Внешние трекеры на этой странице не монтируются. API и изображения требуют
административной сессии, ответы имеют `Cache-Control: no-store`. Страница получает
`noindex, nofollow` и не включается в sitemap. Адрес изображения берётся только
из приватного manifest; выход за каталог набора запрещён, в том числе по symlink.

## Локальная приёмка

1. Открыть `http://localhost:5173/admin-control`, войти в админку.
2. Нажать «Проверка контрольных фотографий». Начнётся реальный прогон.
3. Убедиться, что появились 9 карточек и результаты приходят по одному.
4. Открыть фото, вкладки «Текст», «Исходный», «Оформленный»; при обнаруженной
   таблице проверить вкладку «Таблицы» и сборку таблицы.
5. Проверить остановку после текущего фото и повтор отдельной карточки.
   Ошибка провайдера должна оставаться в карточке и не останавливать очередь.

Приватный набор уже подготовлен в `outputs/ocr-review-dataset/`: только
изображения и manifest с ID и относительными путями. Это игнорируемая Git папка,
её содержимое и архив нельзя коммитить. Исходные фотографии не изменялись.

Состав от 22 октября 2026: 441, 444, 446, 447, 448, 449, затем `h_text_3`,
`h_text_1`, `h_text_2`. Последние три заменяют 450, 451, 452. Новые фотографии
скопированы из `Downloads/test` с проверкой SHA-256; исходники сохранены.
Старые файлы не входят в активный manifest и архив выпуска.
Приватный baseline старого CLI-набора остаётся отдельным набором.

Каждый запуск — новое обращение к модели. Совпадение изображения и кода
не гарантирует одинакового текста двух независимых генераций. Неправильное
имя или потерянный фрагмент остаются ошибкой качества; их нельзя считать
допустимыми только из-за вариативности модели.

При первом создании набора из сохранённого локального manifest:

```powershell
Set-Location C:\Users\olgak\PROJECTS\myworld
node server/scripts/prepareOcrReviewDataset.js
```

Скрипт защищён от перезаписи существующих файлов; повторять его для уже
подготовленного набора не нужно. Для другого набора можно указать исходный
manifest первым аргументом. Для backend можно задать абсолютный
`OCR_REVIEW_MANIFEST_PATH`; по умолчанию используется
`outputs/ocr-review-dataset/manifest.json` относительно корня проекта.

## Проверки без платных API и без БД

```powershell
npm.cmd run test:ocr-review --prefix server
node --test client/tests/documentPageRefactor.test.js client/tests/formattedText.test.js client/tests/formattedLists.test.js client/tests/formattedClipboard.test.js
npm.cmd run build --prefix client
git diff --check
```

Предзагрузчик серверных тестов очищает ключи и `DATABASE_URL`; интеграционный
тест PostgreSQL пропускается. Проверяются доступ, CSRF-токен, повторные запросы,
продолжение после ошибки, повтор восстановления таблиц и пути изображений.
Браузерная проверка выполняется отдельно с подставными ответами и блокировкой
внешних запросов. Успех этих проверок не подтверждает качество текущего провайдера:
оно проверяется Ольгой на настоящем прогоне.

## Подготовка для ручной публикации

Публикацию выполняет Ольга после приёмки и отдельного решения о коммите и push.
После включения принятого кода в `origin/main` на сервере:

```bash
cd /root/myworld
git status --short
# При незакоммиченных изменениях остановиться и сохранить их перед обновлением.
git pull --ff-only origin main
npm run build --prefix client
mkdir -p outputs
```

Приватный набор передаётся отдельно от Git. Локально создать архив:

```powershell
Set-Location C:\Users\olgak\PROJECTS\myworld
node server/scripts/packageOcrReviewDataset.js outputs/ocr-review-dataset-2026-10-22.tar.gz
$reviewServer = Read-Host 'SSH-адрес сервера (например, root@адрес)'
scp outputs/ocr-review-dataset-2026-10-22.tar.gz "${reviewServer}:/root/myworld/outputs/"
```

Скрипт упаковывает только manifest и перечисленные в нём изображения.
На сервере распаковать в отдельный каталог выпуска, сохранив предыдущий набор:

```bash
cd /root/myworld
mkdir -p outputs/ocr-review-2026-10-22
tar -xzf outputs/ocr-review-dataset-2026-10-22.tar.gz -C outputs/ocr-review-2026-10-22
test -f outputs/ocr-review-2026-10-22/ocr-review-dataset/manifest.json
OCR_REVIEW_MANIFEST_PATH=/root/myworld/outputs/ocr-review-2026-10-22/ocr-review-dataset/manifest.json pm2 restart myworld-server --update-env
pm2 save
```

Миграции БД и перезапуск nginx для этой страницы не нужны. После публикации Ольга
проверяет вход в админку, ссылку на страницу, изображения и реальную обработку;
без входа прямые `/admin-api/ocr-review/cases` и адреса изображений должны вернуть
401. Само открытие страницы с действующей сессией запускает платные API-вызовы.
