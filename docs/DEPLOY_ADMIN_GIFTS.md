## Поведение

В карточке пользователя после настроек доступа есть «Подарить обработки»:
по умолчанию 10, можно задать целое число 1–10 000; причина обязательна,
до 500 символов. Форма выделена рамкой, пояснения разделены переносом строки,
поля и кнопка «Подарить» — с отступами, причина вводится в многострочное поле.
Отдельный блок истории с нумерованным списком показывает число, причину и дату по Стамбулу.
Подарки также видны в общих «Начислениях» и истории обработок пользователя.

Подарочный остаток хранится отдельно от стартового бесплатного лимита и пакетов.
Порядок списания: стартовые бесплатные → подарочные → пакетные.
Подарок сохраняется при безлимитном доступе или доступе до даты и расходуется
после его окончания. История обработок, использованные пакеты, платежи,
дата доступа и бесплатный стартовый лимит при начислении не меняются.
Пример: стартовые 3 исчерпаны, из 40 пакетных использованы 22; подарок +10
даёт 10 бесплатных и прежние 18 пакетных, всего 28.

Подарок не считается покупкой и не включает зелёную подсветку.
Защита удаления аккаунтов с платежами сохраняется; подарок сам по себе
не запрещает удаление. Для таблиц оставшийся подарок даёт такой же доступ,
как пакет; отдельная обработка за таблицы не списывается.

Начисление и запись истории выполняются одной транзакцией с блокировкой
пользователя. UUID запроса не позволяет повторному запросу начислить подарок
дважды. При потере ответа повторять с теми же данными в открытой форме.
Изменённые данные с уже использованным UUID отклоняются. Нужны административная
сессия и CSRF; внешние Origin и cross-site запросы отклоняются.
Черновик формы защищён подтверждением закрытия. Во время начисления закрытие
карточки, изменение доступа и удаление блокируются. Изменения доступа нужно
сохранить до начисления подарка.

Миграция `040_gift_processing.sql` добавляет два нулевых счётчика пользователям
и отдельный журнал подарков. Существующие данные не пересчитываются.
Локальная миграция уже применена, настоящим пользователям подарки не начислялись.

Серверные проверки выполняются в искусственных локальных схемах. Проверяются
пакетная история, бесплатный остаток, порядок списания, безлимит и дата,
конкурентные начисления/списания, повтор запросов, ограничения API, CSRF,
история пользователя/админа, классификация покупок и защита удаления.
Доступ к таблицам проверяется с удержанием блокировки до вызова модели:
OCR/LLM не вызываются. Фоновый браузер с подменённым API проверяет 1280/375 px,
защиту черновика, сбой ответа после начисления, повтор с прежним UUID,
новый подарок, историю, навигацию, сохранение и удаление. Внешние запросы
блокируются. Реальный локальный HTTP проверен отдельной admin-сессией:
список, карточка, остаток и история подарков, начисления, отказ без CSRF.

На компьютере:

```powershell
cd C:\Users\olgak\PROJECTS\myworld
git push origin main
ssh root@147.45.246.205
```

На сервере сначала проверить рабочую папку:

```bash
cd /root/myworld
git status --short
```

При наличии изменений остановиться и сохранить их. Если вывод пустой:

```bash
git pull --ff-only origin main &&
npm run db:migrate --prefix server &&
VITE_CLARITY_ENABLED=true VITE_CLARITY_HOSTS=word2you.ru npm run build --prefix client &&
pm2 restart myworld-server --update-env
```

Должна примениться миграция 040. Новых зависимостей и изменений env нет,
`npm install` не требуется. Обновляются и backend, и клиент.

Проверка Ольгой:

```bash
pm2 status myworld-server
curl --fail --silent --show-error https://word2you.ru/api/health
curl --silent --output /dev/null --write-out '%{http_code}\n' https://word2you.ru/admin-api/users
```

Последний запрос без admin-сессии должен вернуть 401. После входа выбрать
согласованный тестовый аккаунт: записать бесплатный/пакетный остатки и расход,
подарить +1 с причиной, проверить прибавку ровно 1, историю в карточке,
«Начислениях» и ЛК. У пользователя без покупок зелёная подсветка не появляется.
Реальную платную обработку для проверки агент не запускает.
