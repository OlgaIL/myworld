# Timeweb: служебные инструкции вне текста документа

16 октября 2026 года у локального гостевого документа №260 OCR правильно
прочитал только «Word2you Записи». Итоговый текст содержал также служебное
напоминание о JSON/corrections: оно было дописано после OCR без границы исходника.

Напоминание перенесено из пользовательского сообщения в системные правила.
После исходного OCR теперь нет служебной приписки; добавлен явный запрет
включать инструкции в результат. Правила corrections сохранены.

Проверено 36 синтетическими тестами: Timeweb, выбор pipeline и оформление.
Использован локальный mock API, платных запросов и production-проверок не было.
Проверка настоящей модели остаётся повторной загрузкой фото Ольгой.
Старые записи в БД не менялись и сами не перерабатываются.

Локально перезапустить `npm run dev` из корня проекта, если backend ещё
работает со старым модулем. Загрузить тот же логотип заново: в «Исходном»
и «Тексте» должна остаться только надпись с фото, без JSON/corrections
и заголовка «Инструкция».

Это отдельный серверный коммит после уже опубликованного `9d3e7ab`.
Перед публикацией доставить его в `origin/main`. Публикует только Ольга.
Проверить рабочую папку сервера; если есть неожиданные изменения, остановиться:

```bash
cd /root/myworld
git status --short
```

При чистой рабочей папке:

```bash
cd /root/myworld &&
git pull --ff-only origin main &&
pm2 restart myworld-server --update-env &&
git log -1 --oneline
```

Зависимости, env, миграции и клиентская сборка этой правке не нужны.
После перезапуска Ольга выполняет проверку:

```bash
curl --fail --silent --show-error https://word2you.ru/api/health
```

Ожидаются `status: ok` и `database.connected: true`. Загрузить публичный
тестовый логотип и сверить «Исходный» и «Текст»; проверить документ с реальной
лексической заменой, что список замен и отмена сохранились. Не переписывать
старые пользовательские записи ради проверки. Агент рабочий сайт не проверяет.
