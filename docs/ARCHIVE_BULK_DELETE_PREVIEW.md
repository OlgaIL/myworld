# Пример массового удаления — 2 ноября 2026

**Обновление 4 ноября:** интерфейс согласован и подключён к настоящему кабинету.
Текущий статус, проверки и команды — в [ARCHIVE_BULK_DELETE.md](ARCHIVE_BULK_DELETE.md).
Ниже сохранена история прототипа до подключения серверной части.

Ольга попросила сначала посмотреть интерфейс. Подготовлен локальный интерактивный
пример: http://localhost:5173/preview/archive-deletion. В нём 59 учебных записей,
сначала видны шесть; данные хранятся только в состоянии React. «Сбросить пример»
восстанавливает записи и сценарии. API удаления, файлы и настоящие записи пример
не использует. Основной кабинет пока работает в прежнем режиме.

## Показанные состояния

- «Выбрать», галочки и выделение карточек; выбор также нажатием на карточку.
  Панель со счётчиком, «Выбрать все 59», «Удалить выбранное (N)», «Отмена».
- По уточнению Ольги «Документов в архиве: 59» и «Выбрать» стоят в одной
  строке с отступом 24 px. «Выбрать»/«Выбрать все» — серое текстовое действие
  без подчёркивания, при наведении чёрное. Поиск расположен ниже строки.
- Выбор всех включает записи за «Показать ещё». Поиск ограничивает набор:
  «Выбрать все найденные: 15». При смене поиска прежний выбор не переносится.
- Подтверждение с точным количеством, составом удаления, сохранением аккаунта,
  покупок и остатка обработок, отсутствием возврата потраченных обработок.
  Список целей фиксируется при открытии подтверждения. Фокус изначально на
  отмене, Tab удерживается внутри диалога; во время выполнения повторный запуск
  и закрытие блокируются. В примере удаление имитируется и отменяется сбросом.
- После трёх успешных одиночных удалений за две минуты появляется ненавязчивое
  предложение выбора. Открытие документа сбрасывает цепочку. «Не сейчас» сохраняет
  отказ в sessionStorage для области примера; при сбросе начинается новая область.
- Успешный результат показывает число удалённых. В дополнительном сценарии
  две записи не удаляются, остаются выбранными и могут быть повторно удалены.

## Проверка

ESLint и сборка прошли. Три проверки покрывают русские формы количества,
подсчёт частичного результата и реальный Gallery с нумерованными названиями.
Browser Plugin проверил выбор 59 при шести отображённых, полное удаление/сброс,
подсказку после трёх удалений, отказ от неё без повторного предложения,
поиск/выбор 15 найденных, частичный результат 13/2. Мобильные выбор и подтверждение
проверены при ширине 390: scrollWidth равен clientWidth. После проверки viewport
возвращён к обычному. Реальных удалений не выполнялось.

## Что ещё не является готовой функцией кабинета

Реальный кабинет не передаёт onDeleteMany, поэтому массовый интерфейс там
не включён. После приёмки понадобятся подключение всех найденных записей до
пагинации, пакетное действие с проверкой владельца и достоверный частичный
результат, согласованные серверные ограничения. Текущий usePhotos.removePhoto
перехватывает ошибки — это нужно исправить до подсчёта успешных удалений и
подключения подсказки к настоящим операциям. Работу с гостевыми записями отдельно
согласовать: там сейчас нет интерфейса удаления пользователем.

Пример доступен только при import.meta.env.DEV; production-ветка не загружает
его страницу и данные. Для просмотра публикация, миграции и перезапуск API
не нужны. Не публиковать как завершённое массовое удаление до приёмки и
подключения серверной части. Изменение пока без коммита.
