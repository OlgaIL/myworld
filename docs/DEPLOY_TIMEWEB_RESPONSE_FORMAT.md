# Timeweb: списки и классификация — 19 октября 2026

В свежем фрагменте лога 27 ошибок: 18 отказов типа list.items, 5 значений
category, 1 значение section, 2 таймаута, 1 HTTP 400. Это фрагмент без
полных ответов модели, а не все ошибки за 48 часов. Из него нельзя узнать,
было ли items строкой, объектом или отсутствовало.

## Что исправлено локально

- Инструкции Timeweb самостоятельные, больше не импортируют OpenAI-prompt.
  Явно заданы поля и примеры heading, paragraph, list, items, ordered/start,
  допустимые категории, разделы и значения textQuality. Правила сохранения
  исходного содержания, corrections и границы служебных инструкций сохранены.
- У category/section исправляются регистр, пробелы и ё/е. Неизвестное или
  отсутствующее значение становится «другое». Содержание документа не меняется.
- Список из объектов с единственным строковым полем text преобразуется в
  строки без удаления пунктов. Если вместо items пришёл цельный текст, он
  сохраняется абзацем: границы пунктов по переносам не угадываются.
- Смешанные типы, пустые пункты, дополнительные неоднозначные данные,
  повреждённый JSON, незавершённые и обрезанные ответы продолжают отклоняться.
- Проверенный formattedContent не подменяется непроверенным formattedText.
  Если документ превышает лимиты общего форматтера (100 блоков / 100 пунктов
  в списке), отклоняется вместо незаметного обрезания.
- Успешное преобразование отмечается безопасной строкой
  `TIMEWEB LLM NORMALIZED:`: только коды и имена полей, без значений и текста.
  Диагностика `TIMEWEB LLM ERROR:` с причиной, полем и HTTP-кодом сохранена.

Яндекс, прямой OpenAI, OCR, сборка таблиц, ключи, env, лимиты времени,
число API-запросов и списания в этой правке не меняются. Новых повторных
запросов или автоматического переключения провайдера нет. Таймауты и HTTP 400
этой правкой не устранены. Старые документы сами не перерабатываются.

Проверено: 69 синтетических тестов прошли, два теста с настоящей БД пропущены;
lint изменённых JS и diff-check. API заменён локальным mock, секреты и БД
отключены тестовым preload. Настоящих платных запросов и production-проверок
агент не выполнял. Снижение реальной частоты ошибок пока не подтверждено.

## Локальная проверка Ольгой

Перезапустить локальный backend, если он уже работал: остановить старый
процесс Ctrl+C в его терминале и запустить `npm start --prefix server`
из `C:\Users\olgak\PROJECTS\myworld`.

Загрузить новый тестовый документ со списком, номерами и заголовком, желательно
с исправлением распознанного слова. Проверить все пункты и их порядок,
начальный номер, «Текст», «Оформленный», список замен и их отмену. Если новый
документ содержит таблицу, проверить также её отдельную сборку. Это ручная
проверка настоящей модели; синтетические тесты не подтверждают её качество.

## Публикация Ольгой после коммита

На компьютере:

```powershell
cd C:\Users\olgak\PROJECTS\myworld
git push origin main
```

На сервере сначала:

```bash
cd /root/myworld
git status --short
```

Если вывод пустой:

```bash
cd /root/myworld &&
git pull --ff-only origin main &&
pm2 restart myworld-server --update-env &&
git log -1 --oneline
```

Для этого состава миграций, новых зависимостей, сборки клиента и изменений
env не требуется. При неожиданных изменениях рабочей папки остановиться,
не выполнять reset/clean и прислать статус.

Ольга проверяет:

```bash
curl --fail --silent --show-error https://word2you.ru/api/health
pm2 status myworld-server
```

Ожидаются status=ok, database.connected=true, процесс online. Проверить новый
документ со списком; старые сохранённые результаты не изменять ради проверки.
После накопления новых обращений посмотреть причины отказов и преобразований:

```bash
pm2 logs myworld-server --err --lines 5000 --nostream | grep -E 'TIMEWEB LLM (ERROR|NORMALIZED):' | grep '"timestamp"' | tail -n 80
```

При сравнении статистики учитывать момент перезапуска: окно 24/48 часов
сначала включает события старой версии. Наличие NORMALIZED означает успешно
принятое преобразование, а не ещё один неудачный вызов LLM.
