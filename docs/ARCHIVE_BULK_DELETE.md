# Массовое удаление архива — локальная реализация, 4 ноября 2026

Интерфейс согласован Ольгой 3 ноября. Подключён настоящий кабинет вошедшего
пользователя: http://localhost:5173/. `/preview/archive-deletion` остаётся
учебным примером. Коммит и публикация пока не выполнялись.

## Поведение

- «Документов в архиве: N» и серая ссылка «Выбрать» в одной строке. Подсказка
  загрузки остаётся непосредственно под кнопкой загрузки, отдельно от архива.
- Выбор карточек и всех найденных, включая записи за «Показать ещё». Смена
  фильтра сбрасывает выбор. Загружаемые фотографии не выбираются.
- Подтверждение фиксирует конкретные имена записей. Новая загрузка, появившаяся
  после открытия диалога, не удаляется. Повторное нажатие во время работы закрыто.
- Запросы по 100 имён; сервер проверяет владельца каждой записи. Нет API-команды
  «удалить всё» без списка. Одиночное удаление использует ту же безопасную логику.
- Эксклюзивная блокировка аккаунта исключает удаление одновременно с загрузкой,
  OCR, сборкой таблиц и переносом гостевых документов. Записи на ручной проверке
  или со статусом processing остаются в архиве и возвращают DOCUMENT_BUSY.
- Подтверждённые удаления исчезают; неудачные остаются выбранными. Отсутствующая
  запись учитывается отдельно и не увеличивает число удалений. После потери
  ответа новые пакеты не отправляются, список перечитывается; интерфейс не
  объявляет неподтверждённое удаление успешным.
- После трёх успешных одиночных удалений за две минуты — предложение выбора.
  «Не сейчас» скрывает его до конца браузерной сессии для этого аккаунта.
- Аккаунт, история покупок, начисленные и потраченные обработки сохраняются.
  Удаление не возвращает обработки. Для гостей новый сценарий удаления не открыт.

## Хранение и восстановление после ошибок

`photoDeletionService` удаляет записи и создаёт задания очистки в одной
транзакции. На каждую запись используется savepoint, чтобы частичный отказ
не отменял остальные. Счётчик documents_deleted_total увеличивается ровно один
раз на действительно удалённую запись. Непосредственного unlink до COMMIT нет.

Используется существующая очередь account_deletion_jobs/account_deletion_files
из миграции 034 и её фоновый обработчик. Она не требует удаления аккаунта:
задание содержит только пути файлов. После COMMIT выполняется немедленная
очистка, при ошибке — повтор фоновым worker после перезапуска/в следующем цикле.
Клиент сообщает, если исходные файлы ещё ожидают очистки. Общие файлы защищены
проверкой живых ссылок; произвольные пути, каталоги и ссылки не удаляются.
Гостевые копии/исходники и завершённые собственные file intents учитываются;
пустая claim-связь сохраняется как защита от повторного переноса удалённого фото.

Для массового удаления новой миграции нет. Миграция 047 — отдельная уже
подготовленная задача стабильных названий, локально она применена.

## Публикация — выполняет Ольга после отдельного согласованного коммита

Новых зависимостей нет. Нужны сборка клиента и перезапуск API; переустановка npm
для этой функции не требуется. Перед pull рабочая копия сервера должна быть чистой.

```bash
ssh root@147.45.246.205
cd /root/myworld
git status --short
git pull --ff-only origin main
cd /root/myworld/server
npm run db:status
```

Если вместе публикуется нумерация названий и ожидает применения **только**
047_document_display_titles.sql, выполнить:

```bash
cd /root/myworld/server
npm run db:migrate
npm run db:status
```

Для одного массового удаления миграций нет. Затем:

```bash
cd /root/myworld/client
npm run build
cd /root/myworld
pm2 restart myworld-server --update-env
pm2 status myworld-server
curl -fsS http://127.0.0.1:4000/api/health
```

Ольга проверяет в браузере после Ctrl+F5: счётчик/выбор на одной строке,
отмена без удаления, удаление только выбранных тестовых записей, сохранение
платного остатка. Агент production не открывает и не проверяет.
