## Цель

Пользователь собирает фотографии страниц в один документ, читает их подряд,
копирует весь текст и при необходимости снова получает отдельные документы.
Изображения и результаты распознавания страниц сохраняются раздельно.

## Согласованные требования

- Функция доступна только авторизованным пользователям, включая бесплатные
  аккаунты в пределах их действующего доступа. Гостевой сценарий прежний;
  новые операции недоступны гостям также через API.
- 15 ноября Ольга согласовала максимум 25 страниц на документ: при загрузке,
  добавлении страниц и объединении. Лимит задаётся одной настройкой.
- При выборе нескольких фотографий предложить: страницы одного документа
  или отдельные документы. По решению Ольги по умолчанию — **отдельные документы**;
  выбор оформляем радиокнопками перед запуском загрузки.
- Уточнение 18 ноября: при выборе одного фото сразу запускать обычную загрузку,
  без диалога выбора режима. Проверки остатка обработок и лимитов сохраняются;
  радиокнопки выбора режима показываются только при выборе нескольких фото.
- В режиме одного документа фотографии последовательно загружаются в него.
  Порядок страниц хранится явно, независимо от времени завершения обработки.
- В документе страницы показаны подряд. Общие заголовок и краткое описание
  показываются один раз в начале. Уточнение Ольги 16 ноября: у каждой страницы
  показывать собственные название и короткую аннотацию, как в перестановке.
  Уточнение 18 ноября: у первой страницы не дублировать их под общей шапкой;
  у второй и последующих показывать. Номер и действие первой страницы остаются.
- Копирование страницы остаётся существующей иконкой внутри текста/вкладки,
  дополнительной нижней кнопки нет. «Скопировать всё» — крупнее, справа от
  названия документа, на телефоне под ним. «Добавить страницы» — рядом с датой,
  статусом и числом страниц над названием; внизу справа также привычный «+».
  Кнопка перестановки называется «Изменить порядок страниц».
- Уточнение 18 ноября: дата/статус/количество страниц выровнены слева,
  добавление — справа по краю копирования. В диалоге добавления три кнопки
  «Отмена», «Добавить из архива», «Выбрать фото»; отдельной ссылки нет.
  Под счётчиками — тонкий разделитель. «Разделить на документы» оформляется
  кнопкой как перестановка; в подтверждении предложения с отдельных строк.
  После успешного общего копирования обе кнопки показывают галочку и
  «Скопировано» 5 секунд, с сохранением размеров кнопок.
- У каждой страницы сохраняются собственные нынешние вкладки: «Текст»,
  «Исходный (без замен)», «Оформленный» и другие по действующим условиям.
  Между страницами добавляется «Страница N из M»; общий переключатель вкладок
  вместо постраничных не вводим. Уточнено Ольгой после упрощённого макета 9 ноября.
- Порядок при загрузке — показанный порядок файлов, при объединении архива —
  по времени загрузки от ранних к поздним. Страницы можно переставлять вручную.
- Последнее уточнение Ольги: **первую версию делаем без общей LLM**.
  Автосортировку и генерацию общей шапки откладываем. Это заменяет промежуточные
  решения об автоматическом вызове/обновлении общего описания.
- Сборка, разборка, перестановка и копирование используют сохранённые результаты:
  без OCR, LLM и списаний. При догрузке обрабатываются только новые фото.
- Кнопка «+» внутри документа добавляет новые фотографии в его конец.
- Уточнение 18 ноября: обычная загрузка отдельных документов остаётся в архиве
  с карточками/статусами. Для загрузки внутрь документа показывать текущую страницу,
  прокручивать к её плашке и отображать статус подготовки/загрузки/обработки.
  Следующая страница получает фокус по очереди, без прокрутки на каждом опросе.
  При добавлении из архива — статус добавления, затем прокрутка к новой странице
  и отметка «Добавлена из архива. Обработки не списаны», без OCR и расхода обработок.
- Любую страницу можно выделить в отдельный документ. Ссылка называется
  «Убрать из документа», рядом справа — «Страница N из M». Диалог поясняет,
  что страница сохраняется отдельной записью в архиве. Действие
  «Разделить на отдельные документы» делает каждую страницу самостоятельной.
- В архиве многостраничный документ занимает одну карточку с обозначением
  многостраничности и количеством страниц.
- Уточнение 17 ноября: чекбоксы скрыты по умолчанию. Только кнопка «Выбрать»
  включает выбор и панель удаления/объединения; отмена очищает выбор и скрывает её.
  Пакетная загрузка по-прежнему только для авторизованных, гостевой сценарий прежний.
- Из выбранных в архиве документов можно объединить только одностраничные.
  Если выбран хотя бы один многостраничный, блокируется вся операция;
  частичное объединение остальных не выполняется.
- Сообщение: «Пока можно объединять только одностраничные документы.
  Уберите многостраничные из выбора».
- История прежних объединений и восстановление прежних групп не нужны.
- Удаление из архива удаляет весь многостраничный документ с его страницами.
  Внутри документа вместо удаления страницы предлагается выделение в отдельный
  документ; исходное изображение и результат при этом сохраняются.
- При чтении — общие заголовок и описание сверху из сохранённых данных первой
  страницы при создании; собственные названия/описания страниц также показываем
  по уточнению 16 ноября и храним для перестановки/разделения. Общая кнопка копирует содержимое страниц без
  служебной шапки; содержательные заголовки из самого текста сохраняются.

## Предлагаемая архитектура

Основа текущей модели аккаунта — записи `photos`: изображение, результаты
обработки, статусы и метаданные. Сохранить их как независимые записи страниц.
Над ними добавить сущность документа и связь с сохранённой позицией страницы.
Это направление проектирования, точную схему зафиксировать на этапе 1.

- У документа — стабильный ID, владелец и общие метаданные.
- У страницы — стабильный существующий ID, принадлежность документу и позиция.
  Страница принадлежит одному документу; совместного использования нет.
- Заголовок и описание документа не привязывать к текущей первой странице.
  Перестановка не должна сама по себе менять название документа.
- Собственные заголовок, описание и результаты страницы сохранять для
  выделения и разделения; объединение не переписывает распознанный текст.
- Существующие одностраничные документы и ссылки на них сохранить.
  Старую ссылку на страницу после объединения направлять к ней внутри документа.
- Объединение, выделение, разделение и перестановку выполнять транзакционно.
  Проверять владельца каждого объекта, актуальность состава и уникальность
  позиций на сервере. Повтор запроса не должен создавать копии страниц.
- Не выводить порядок из массива ответа API, `created_at` или очередности OCR.
- Гостевые таблицы и перенос гостевого результата в аккаунт сохраняют нынешний
  сценарий; перенесённый результат становится обычным одностраничным документом.

## Решения для этапа 1

Ключевые решения уточнены с Ольгой; остальные технические предложения
и подробности приведены в [проекте этапа 1](MULTIPAGE_DOCUMENTS_DESIGN.md).

1. Выбор загрузки: две радиокнопки, по умолчанию «Отдельные документы».
   Внутри «+» выбор не нужен: страницы всегда добавляются в открытый документ.
2. Начальный порядок при загрузке — порядок предварительно показанных файлов;
   при объединении архива — время загрузки от ранних к поздним с устойчивым
   дополнительным ключом. Перед подтверждением показать миниатюры и порядок.
3. LLM не вызывается для сборки документа, включая первоначальную сборку.
   Автосортировка отложена по последнему решению Ольги, первая версия — ручной порядок.
4. По уточнению Ольги 18 ноября название и аннотация следуют текущей первой
   странице, включая перестановку и удаление первой. Догрузка в конец не меняет
   первую страницу; дата в архиве остаётся прежней.
   Разделение/выделение используют собственные сохранённые данные страниц.
5. Списание: сохранять действующие правила обработки на уровне фотографии.
   Объединение, разделение и перестановка не запускают повторное распознавание
   и не списывают обработки. До загрузки объяснять число обрабатываемых страниц.
   Уточнение Ольги 14 ноября: если обработок меньше выбранных фото, весь выбор
   не запускаем; автоматически часть не обрабатываем. Сообщение с актуальными
   числами: «1 фото — 1 обработка. Вы выбрали 5 фото, а доступно 3 обработки.
   Выберите не больше 3 фото или пополните баланс».
6. При частичной ошибке сохранять успешные страницы, показывать ошибку у нужной
   страницы и повторять только её. Для общего копирования явно сообщать о
   пропущенных/неготовых страницах; не выдавать неполный текст за полный.
   14 ноября Ольга согласовала объединение страниц с ошибкой или без обработки:
   само объединение обработку не запускает. Во время загрузки, обработки или
   проверки заявки объединение недоступно. Повтор ошибки — внутри документа,
   у соответствующей страницы, без повторной обработки успешных соседних.
   Показывать «Загружено: N, обработано: M», у ошибки — «Обработка не списана»
   по фактическому учёту и действие «Повторить обработку».
   15 ноября Ольга уточнила: загрузить другое фото на то же место можно только
   у страницы с ошибкой обработки или с результатом «Текст не найден» (просто
   фото без текста). Позиция страницы сохраняется. В остальных случаях другое
   фото добавляется отдельной загрузкой, без замены существующей страницы;
   обработка нового фото — по действующим правилам.
7. Перестановка: отдельный режим с миниатюрами, перетаскиванием и доступными
   кнопками перемещения для телефона и клавиатуры.
8. После выделения остаётся одна страница — обычный одностраничный вид.
   «Убрать из документа» у единственной страницы не предлагать; пустые документы не хранить.
9. Копирование: у каждой страницы свой активный вариант. Для общего копирования
   15 ноября согласована сборка выбранного варианта каждой страницы в порядке
   документа, через пустую строку, без служебных названий и номеров.
   Уточнение 17 ноября: диалог «Скопируем содержимое всех открытых вкладок
   в буфер обмена. Проверьте открытые вкладки». Открытые «Таблицы» автоматически
   переключаем на доступный «Оформленный», указывая номера переключённых страниц.
   Недоступную вкладку не выбираем: объясняем, что скопируются только таблицы.
   Пользователь может вернуться к страницам или подтвердить копирование.
   «Между страницами — пустая строка» и пояснение о служебных названиях —
   с переводом строки. Одинаковая кнопка «Скопировать всё» сверху и внизу справа,
   без полужирного текста; число страниц рядом со статусом теперь полужирное.
   Вкладки, оформление и условия доступности сохраняются по нынешним правилам.
   Не склеивать таблицы и не переписывать переходы между страницами через LLM.
   При ошибке буфера показывать ошибку; скачивание текста — отдельное предложение.
10. 15 ноября согласованы дата, поиск и счётчики: при объединении дата самой
    поздней фотографии, перестановка/догрузка карточку не поднимают; после
    разделения возвращаются даты исходных фото. Поиск по всем страницам,
    одна карточка документа; фильтр тегов учитывает все страницы. В архиве
    считаем документы, на карточке показываем количество страниц. Расход
    обработок — по фотографиям по действующим правилам, объединение готовых
    страниц бесплатно. Лимит 25 страниц и условия замены фото согласованы
    15 ноября.

- Выбор режима загрузки; создание одного документа с последовательной загрузкой
  страниц; «+» для добавления в конец существующего.
- Сохранять уже загруженные страницы при обрыве; предусмотреть восстановление
  состояния после перезагрузки и безопасный повтор без дублирования.
- Статус каждой страницы и общий прогресс, повтор отдельной ошибки.
- Показ страниц подряд с единой шапкой и собственными вкладками каждой страницы;
  номер «Страница N из M», отдельное и общее копирование.
- Карточка архива: значок, количество страниц и согласованные статусы.
- Результат: сценарий «выбрать 5 фото → один документ → скопировать» работает
  локально; режим отдельных документов и гостевая обработка не ухудшились.

### 4. Управление страницами и объединение из архива

- Предпросмотр объединения выбранных одностраничных документов и объяснение:
  «Объединить в один документ, чтобы читать и копировать весь текст вместе.
  Позже его можно разделить на отдельные документы».
- Блокировка всей операции при выборе многостраничного документа.
- Ручная перестановка, выделение страницы и разделение всего документа.
- Удаление карточки целиком с явным количеством страниц в подтверждении.
- Результат: сборка и разделение сохраняют изображения, текст, исправления,
  таблицы и действующие связи страницы; списания не возникают.

### 5. Устойчивость загрузки, повторов и учёта

- Проверить обрыв и возврат в загрузку, распознавание конкретной страницы,
  повтор запроса после потери ответа и конфликт двух вкладок.
- Подтвердить отсутствие внешних OCR/LLM-вызовов и списаний при всех структурных
  действиях над готовыми страницами, в том числе повторной сборке и разделении.
- Защитить обработку одной страницы от дублирующих запросов и перепроверять
  остаток перед каждой расходующей обработкой, включая две вкладки.
- Результат: успешные страницы сохранены, вызовы и списания не дублируются,
  ошибки не приводят к потере документа или скрытой частичной операции.

### 6. Сквозная приёмка и подготовка выпуска

- Проверить новый аккаунт и существующий архив, гостя и вход после гостевой
  обработки, отсутствие/нехватку баланса, частичные ошибки и повтор запросов.
- Проверить поиск по любой странице, старые ссылки, пагинацию и счётчики,
  текстовые варианты/таблицы, большой документ и вставку скопированного текста.
- Проверить мобильный интерфейс, клавиатуру, сохранение порядка после обновления
  и конфликты операций. Выполнить профильные тесты, lint и сборку.
- При просмотре браузера использовать Browser Plugin, без перехвата мыши.
- Подготовить для Ольги миграцию, резервное копирование, точные команды выпуска,
  рестарта и проверок, а также ограничения отката. После создания многостраничных
  документов откат к старому коду может быть несовместим: определить безопасный
  порядок заранее, не удалять новые связи ради простого отката.
- Результат: локальная приёмка и готовая инструкция. Публикацию и проверки
  production выполняет только Ольга; команды выдаются в чате по одному шагу.

## Объём и модель разработчика

Это крупная продуктовая доработка из шести последовательных этапов: новая
сущность затрагивает БД, API, загрузку, архив и действия над содержимым.
Самые чувствительные части — миграция старых записей, атомарность операций,
списания, устойчивость загрузки и сохранность связанных результатов страниц.
Точный срок оценить после этапа 1; обещание сделать за один проход ненадёжно.

Рекомендация для разработки: GPT-6.1 Sol / High. Для проверки схемы миграции
и конфликтов данных можно повысить усилие до Extra High. Astra не обязательна;
её запуск требует отдельного предварительного разрешения Ольги.
Это инженерная оценка применительно к задаче, не гарантия результата модели.
[Официальная документация по моделям и уровням усилия](https://learn.chatgpt.com/docs/models).
Дополнительная модель для сборки/сортировки внутри продукта в первой версии
не нужна: по последнему решению Ольги используем готовые результаты.

## За рамками первой итерации

- Многостраничные документы для гостей.
- Объединение с участием хотя бы одного многостраничного документа.
- История объединений и восстановление прежних групп.

- Автоматическое склеивание таблиц или смысловое переписывание общего текста.
- Общий рефакторинг OCR и смена основного провайдера распознавания.
