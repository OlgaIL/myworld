# Inspectlet

Локальная замена Clarity на Inspectlet, проект `390286863`, основной домен
`word2you.ru`. Яндекс Метрика сохранена. Дополнительные события, метки и
идентификация через API не добавлены. Автоматическая запись SPA, один SDK
на документ. Ошибки загрузки счётчика не блокируют приложение.

## Согласованные тексты

Уведомление:

> Мы используем cookie, чтобы сайт работал корректно, сохранял вашу сессию и помогал нам улучшать сервис с помощью аналитики.

Политика, раздел «Файлы cookie и аналитика»:

> Для аналитики использования сайта и улучшения его работы используются Яндекс Метрика и Inspectlet, которые используют файлы cookie.

Кнопки уведомления сохранены: «Без записи визитов» и «Разрешить запись».
Размер текста 14px, цвет `#344054`; общий дизайн сохранён.

## Поведение

- SDK подключается после разрешения. Старые согласия другого сервиса не используются.
- Отказ и отзыв согласия доступны; отзыв после загрузки SDK перезагружает страницу.
- Классы `inspectletIgnore` скрывают поля email/кода и email в подтверждении входа.
  Обычные документы и отображаемые данные аккаунта специально не маскируются.
- Административные и неизвестные маршруты не запускают SDK. Переход в такой
  маршрут после старта SDK выполняется полной навигацией без монтирования
  административного содержимого в документе с загруженным SDK.
- Сохранена защита URL: страницы с query/fragment и небезопасным referrer
  сейчас не записываются. Это ограничивает охват рекламных визитов.
- Локально и в dev SDK выключен; отдельное зеркало не подключено.

Официальные инструкции:
[установка](https://www.inspectlet.com/docs/install),
[маскирование](https://www.inspectlet.com/docs).

## Публикация — выполняет Ольга

### Исправление оформления replay — 5 ноября

В переданной записи stylesheet `/assets/index-BOHuA54G.css` не имел `sheet`.
HTTP-статус не установлен: CORS, недоступность старого asset и сбой кеширования
остаются гипотезами. Сервер разрешает CORS только своим origin; наличие
`crossorigin` у LINK само по себе не доказывает причину отказа. CSS caching
в проекте включён. Обычная Vite-сборка очищает `dist`, поэтому старые хешированные
assets не гарантированно доступны после следующей публикации.

Сборка теперь помещает содержимое CSS приложения в `<style
data-word2you-replay-css>` внутри `index.html` **до** создания prerender-страниц.
CSS попадает в DOM, без зависимости от отдельного запроса, CORS, кеша Inspectlet
и срока хранения хешированного файла. Файл CSS также остаётся в сборке;
настройки Vite/Inspectlet и серверный CORS не меняются. HTML увеличивается
примерно на 112 КБ до gzip; отдельное кеширование CSS браузером для этих страниц
больше не используется. Внешний декоративный шрифт остаётся внешним с fallback.
В репозитории нет CSP, запрещающей inline CSS; фактические заголовки production
в этом чате не проверялись. Старые записи этим изменением не исправляются.

Официальный [inspectlet-href](https://docs.inspectlet.com/docs/overriding-css-location-for-playback)
заменяет адрес LINK при replay, но требует доступного CSS по этому адресу.
Непроверенные data URL для CSS и открытие CORS всего backend не используются.

Проверено локально: 124 клиентских теста и production/SSR-сборка прошли.
В изолированном Edge внешний LINK и встроенный CSS дали одинаковые пиксели
на странице искусственного результата при ширинах 1280 и 375 px. Настоящий
SDK захватил **полный** CSS (сравнение всей сериализованной строки), учебный OCR
до последней строки, состояния загрузки/ожидания/ошибки/повтора/результата.
SPA, маскирование email/OTP входа, исключение админки, отзыв согласия и
блокировка SDK прошли. Все внешние запросы перехвачены; отправок в Inspectlet 0.
Это проверка DOM/данных SDK, **не** облачного воспроизведения или production.
Локальные сценарии/артефакты: `work/extend-inspectlet-replay-check.cjs`,
`work/verify-inspectlet-replay-css.cjs`, `work/inspectlet-replay-css-review.json`;
в коммит не включать. Проверка использует текущий рабочий каталог с другими
незавершёнными правками; они в коммит Inspectlet не входят.

### Фото — только согласованный локальный прототип

`GET /api/photos/:name` требует авторизации и поиска владельца, гостевой
`/api/guest/documents/:id/file` — гостевой cookie. Без сессии сайта replay
не может получить файл. Защита остаётся; публичные URL не добавлены.
Официальный [inspectlet-src](https://docs.inspectlet.com/docs/modifying-recorded-image-url)
подменяет адрес изображения, но не даёт доступа к защищённому файлу.

Ольга разрешила **только локальный прототип** с искусственными фото и блокировкой
внешних отправок. В рабочем клиенте передачи копий фото пока нет.
Предложение: после согласия передавать уменьшенный снимок как data URL, без
cookies, токенов и публичных ссылок. В локальном экземпляре SDK обнаружено
обрезание `data:image` до 40 000 символов; исходное предложение 300 КБ отменено.
Проверяемый предел прототипа — 38 000 символов, максимум 1200 px; если снимок
не помещается, его нельзя молча отправлять обрезанным.
Учебное изображение 900×1200 с 20 строками пришлось уменьшить до 295×393
(29 063 символа). SDK захватил data URL; отдельная локальная страница открыла
снимок без cookie/API. Оригинальный файл в интерфейсе не подменялся.
Для мелких букв/рукописей качество такого уменьшения не подтверждено;
прототип не принят как окончательное фото-решение. Возможный следующий шаг —
уточнить у Inspectlet поддержку большего inline-изображения для этого проекта;
сообщения провайдеру не отправлялись.

Копия будет частью записи Inspectlet. Удаление исходника или отзыв согласия
не удаляют уже переданные данные. [Срок хранения](https://www.inspectlet.com/plans)
зависит от тарифа (1–24 месяца); тариф проекта и конкретный срок здесь не
установлены. До реализации нужны согласованный срок/порядок удаления записей,
проверка качества уменьшения и отдельное разрешение Ольги на передачу фото.
Прототип и перехват SDK не доказывают работу облачного replay.

Изменения сначала должны попасть в согласованный коммит и `origin/main`.
Эта инструкция не означает, что push или публикация уже выполнены.

```sh
ssh root@147.45.246.205
cd /root/myworld
git status --short
# Если есть незакоммиченные изменения на сервере, остановиться.
git pull --ff-only origin main
VITE_INSPECTLET_ENABLED=true VITE_INSPECTLET_HOSTS=word2you.ru npm run build --prefix client
```

Миграции БД, перезапуск PM2 `myworld-server` и nginx не нужны: меняется клиент.
Для отключения с последующей перезагрузкой открытых вкладок:

```sh
cd /root/myworld
VITE_INSPECTLET_ENABLED=false VITE_INSPECTLET_HOSTS=word2you.ru npm run build --prefix client
```

## После публикации — проверяет Ольга

1. Открыть сайт в новой вкладке без старого состояния; проверить короткое
   уведомление и тёмно-серый текст кнопок. До разрешения нет Inspectlet SDK.
2. Разрешить запись, пройти загрузку искусственного документа, ожидание,
   результат, ошибку и повтор, переходы по страницам. В Network — один
   `inspectlet.js?wid=390286863`, нет запросов Clarity; Метрика остаётся.
3. В Inspectlet открыть новую запись, проверить действия, документы и имя
   аккаунта, скрытие полей входа/кода, отсутствие административных страниц.
4. Проверить отказ, отзыв согласия в политике и работу сайта с заблокированным SDK.
5. Настройки самого проекта могут дополнительно скрывать содержимое: подтвердить
   фактическую видимость в новой записи. Старые записи не меняются задним числом.
