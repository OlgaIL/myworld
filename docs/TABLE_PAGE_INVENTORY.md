## Общая логика

- На сложной странице сначала проверяется весь лист. Обзор возвращает только
  области таблиц, без значений ячеек и предположений о числе колонок плотной шапки.
- Модель получает фото и независимые геометрические ориентиры. Полнота обзора
  проверяется по найденным клеточным сеткам и OCR в областях длинных линий.
  Проверяются границы, пересечения, слияние соседних таблиц и покрытие слов.
  Две области в ответе не принимаются автоматически только потому, что прежний
  детектор смог восстановить две сетки.
- Для пунктирного тела таблицы добавлено восстановление границ колонок по
  сплошным линиям шапки. Требуются подтверждённые вертикальные продолжения в теле;
  горизонтальные линии задают строки. Нет опоры в изображении — сетка не выдумывается.
  Геометрия не задаётся именем квитанции, номером документа или ответом с числами.
- Каждая таблица целиком вырезается в памяти вместе с названием и шапкой.
  Отдельный запрос GPT получает её карту/OCR. Полная независимая сетка определяет
  число колонок, sourceRows и объединения. Значения модели не определяют сами
  границы, по которым затем проходят проверку.
- У неизвестной сетки остаётся проверка по региональным координатам OCR;
  headerRows проверяются на точное покрытие колонок без дыр и пересечений.
  Неподтверждённое размещение чисел помечается для сверки, а не объявляется
  проверенным по пикселям. Это ограничение, а не гарантия любых документов.
- Проверяются каждый фрагмент, полнота набора, порядок и размещение среди
  обычного текста. Отклонённые значения не пересылаются следующему запросу
  как источник. Разрешено одно адресное исправление неудачной части на всю операцию.
- До десяти таблиц: максимум 12 внутренних вызовов (обзор + 10 частей + одно
  исправление), общий таймаут сложной цепочки не меньше 120 секунд. Один запуск
  пользователя расходует одну попытку; все фактические вызовы и токены учитываются.
  Для model_calls нужна миграция 046. Переключения на Astra/Gemini нет.

Простая обработка при выключенном переключателе сохраняет прежний путь.
Для старых отказов размещения/количества новый осмысленный повтор предлагается
только при включённой цепочке; выключенный выпуск не рекламирует эксперимент.
Описание и оформление должны сначала завершиться: при recognized вкладка
«Таблицы» остаётся серой и недоступной по ранее согласованному правилу.

## Публикация выполняется только Ольгой по отдельному решению

По умолчанию TABLE_PAGE_INVENTORY_ENABLED=false: новая цепочка сама не включится
при доставке кода. Чтобы включить принятую локально новую цепочку, установить true в
server/.env и применить миграцию 046. Для предшествующего комплекта таблиц нужны 041–045
и sharp; проверить ожидающие миграции до запуска. Агент production не трогал.

После доставки согласованного комплекта файлов:

Для sharp 0.35.5 требуется Node.js не ниже 20.9.0. Сначала проверить версию;
при более старой версии не продолжать установку зависимостей до обновления Node.js.

```bash
ssh root@147.45.246.205
cd /root/myworld/server
node --version
npm ci --omit=dev
node --input-type=module -e 'import "dotenv/config"; import fs from "node:fs"; import pg from "pg"; const db=new pg.Client({connectionString:process.env.DATABASE_URL}); try { await db.connect(); const applied=new Set((await db.query("select filename from schema_migrations")).rows.map(r=>r.filename)); console.log(fs.readdirSync("db/migrations").filter(n=>n.endsWith(".sql")&&!applied.has(n)).sort()); } finally { await db.end(); }'
npm run db:migrate
npm run db:status
# В server/.env значение TABLE_PAGE_INVENTORY_ENABLED выбирает Ольга.
cd /root/myworld/client
npm run build
cd /root/myworld
pm2 restart myworld-server --update-env
pm2 status myworld-server
curl -fsS http://127.0.0.1:4000/api/health
```
