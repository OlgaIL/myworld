# Списки и подпункты — 20 октября 2026

## Состав правки

Timeweb-prompt явно сохраняет типы маркеров, продолжения пунктов и порядок.
У списка появилось необязательное поле `level`: 0 (обычный), 1 или 2.
Вложенный блок следует после родителя и относится к его последнему пункту;
продолжение родительского списка оформляется отдельным блоком с `start`.
Вложенность разрешена только по явным признакам исходника. Смена цифр на
маркеры без отступов означает два отдельных списка, а не доказанную вложенность.

Общий форматтер сохраняет level, не удаляет количества из пунктов и учитывает
начальный номер. Валидатор Timeweb отклоняет пропущенные/недопустимые уровни.
При явных смешанных маркерах сверяет число пунктов обоих типов с OCR:
расхождение сохраняет результат, но добавляет видимое предупреждение и безопасный
код `LIST_STRUCTURE_REQUIRES_REVIEW` в существующий лог NORMALIZED.
Проверка эвристическая: без маркеров или при неоднозначной нумерации она
не доказывает правильность структуры. Фото по-прежнему не передаётся текстовой
модели. Новых запросов, повторов или списаний нет.

Клиент отображает вложенные списки внутри последнего пункта родителя.
Копирование «Оформленного» со списками передаёт HTML и обычный текст вместе,
сохраняя структуру для вставки в Word. Копирование исходника остаётся обычным.
Вручную улучшенный текст поддерживает списки с отступами (2 пробела на уровень).
Подсветка/отмена замен используют прежние индексы блоков и пунктов.
Таблицы и маскирование Clarity сохранены.

Для простого смешанного списка prompt получает явные границы пунктов из OCR.
Неоднозначные и вложенные списки, отдельные абзацы, несмежные номера,
ввод больше 40 000 символов и списки больше 100 пунктов не получают подсказку.
Подсказка увеличивает входной prompt; дополнительных completion нет.
Реальный completion на OCR №600 и две новые HTTP-загрузки того же фото
вернули 3 номера + 2 маркера с продолжением внутри последнего пункта.
Сохранённый локальный №600 исправлен с резервной копией в work/; квоты и
счётчики его владельца не менялись. Остальные старые документы автоматически
не перерабатываются. Production агент не вызывал.

Проверено локально: 77 серверных тестов прошли (2 проверки с настоящей БД
пропущены), 93 клиентских теста прошли, lint изменённых JS/JSX и
production-сборка с флагами Clarity успешны. Проверены React-рендер вложенного
списка, HTML и текст копирования, прежние списки/таблицы/замены, ограничения
уровней и предупреждение о потере маркеров. API заменён локальным mock,
БД и ключи отключены preload. У сборки остаётся прежнее предупреждение о
JS-чанке больше 500 kB; lint сообщает устаревшие данные baseline-browser-mapping.

После локальных TIMEWEB_TIMEOUT добавлена диагностика transportCode из
закрытого списка технических кодов и timeoutStage (соединение/общий дедлайн/
транспорт). Текст сетевой ошибки, URL, ключи и документы в лог не попадают.
Число запросов и таймаут не изменены. Настоящий HTTP retry и три загрузки через
рабочий backend завершились за 4,1–5,9 с. 22 октября Ольга сообщила, что
локальная обработка работает. Первопричина прежних сетевых timeout не
установлена; текущий успех не считается её исправлением. После перезапуска
backend нужно войти заново: express-session использует память процесса.

## Локальная проверка

Автоматические проверки без реальных API и секретов:

```powershell
cd C:\Users\olgak\PROJECTS\myworld
npm run test:timeweb --prefix server
npm test --prefix client
npm run lint --prefix client
$env:VITE_CLARITY_ENABLED='true'
$env:VITE_CLARITY_HOSTS='word2you.ru'
npm run build --prefix client
```

В терминале работающего сайта остановить процесс Ctrl+C. Затем:

```powershell
cd C:\Users\olgak\PROJECTS\myworld
npm run dev
```

На localhost:5173 загрузить фото с тремя нумерованными пунктами и двумя
маркерными. Ожидается 3 + 2, продолжение последнего пункта остаётся в нём.
Проверить «Текст», «Оформленный», замены/их отмену. Вложенный отступ появляется
только если распознавание сохранило явные признаки вложенности.
Во вкладке «Оформленный» нажать копирование и вставить в Word с сохранением
исходного форматирования. Проверить номера, маркеры, отступы и весь текст.
Проверить также старую запись и документ с таблицей.
Browser Plugin сейчас недоступен: визуальная проверка вкладок и вставка в Word
пока не подтверждены. Правильные 3+2 подтверждены реальными ответами API.

## Публикация Ольгой после проверки, отдельного коммита и push

Коммит со списками отделён от админского OCR reviewer, включая общие файлы
`DocumentTextVariants.jsx`, `aiService.js` и ROADMAP. Остальные незакоммиченные
изменения не включать в публикацию. Не использовать `git add .`.

После подготовленного коммита на компьютере:

```powershell
cd C:\Users\olgak\PROJECTS\myworld
git push origin main
```

На сервере проверить рабочую папку:

```bash
cd /root/myworld
git status --short
```

При пустом выводе:

```bash
cd /root/myworld &&
git pull --ff-only origin main &&
VITE_CLARITY_ENABLED=true VITE_CLARITY_HOSTS=word2you.ru npm run build --prefix client &&
pm2 restart myworld-server --update-env &&
git log -1 --oneline
```

Миграций, новых зависимостей и изменений server/.env не требуется.
После публикации Ольга выполняет:

```bash
pm2 status myworld-server
curl --fail --silent --show-error https://word2you.ru/api/health
```

Ожидаются online, status=ok и database.connected=true. Ольга проверяет новый
документ со смешанным списком, вкладки и вставку в Word; старые результаты сами
не изменятся. При необходимости посмотреть новые безопасные предупреждения:

```bash
pm2 logs myworld-server --err --lines 1000 --nostream | grep -E 'TIMEWEB LLM (ERROR|NORMALIZED):' | tail -n 30
```

Предупреждение о структуре не считается неудачным вызовом LLM: текст сохранён,
дополнительного запроса нет. Проверку production агент не выполняет.
