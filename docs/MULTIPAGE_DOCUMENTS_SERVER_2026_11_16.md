# Многостраничность: серверная основа и макет на согласование

Статус 16 ноября 2026: хранение и структурные операции этапа 2 реализованы
и проверены локально. Весь функционал ещё не завершён: пакетная загрузка,
догрузка/замена фото и подключение настоящего интерфейса — следующие этапы.
Макет подготовлен для согласования Ольгой до реализации интерфейса.

## Реализовано

- Миграция 049: контейнеры документов, явный порядок страниц, старые ссылки,
  квитанции операций и таблицы будущих загрузочных сессий.
- Каждое старое/новое фото сохраняет прежние ID, файл, тексты, таблицы,
  исправления и заявки. Триггер охватывает обычную загрузку, гостевой перенос
  и прямые служебные вставки; пустой контейнер или фото без него не коммитятся.
- Чтение документа/архива и положения страницы; объединение только
  одностраничных, перестановка, выделение, разделение и удаление документа.
- Версии структуры, защита владельца, повтор запроса по operationId без
  повторного изменения, отказ при активной обработке/проверке/загрузочной сессии.
- Старый DELETE фотографии отказывает для внутренней страницы группы.
  Удаление всей группы использует прежнюю проверку файлов и долговечную очередь,
  но откатывает все страницы документа при ошибке любой из них.
- Метаданные группы фиксируются отдельным снимком (`metadata_frozen`).
  Перестановка/выделение не меняют шапку; разделение восстанавливает метаданные
  страниц и их даты. Пока первоначальная страница не обработана, снимок pending.
- Единственный лимит — DOCUMENT_PAGE_LIMIT=25 в server/config/documentLimits.js;
  API отдаёт его клиенту. Объединение, перестановка и разделение не запускают
  OCR/LLM и не изменяют баланс. Расходующие операции по фото остаются прежними.
- Архив отдаёт теги и поисковый текст всех страниц одной карточкой документа.
  `/api/me` добавляет documentsStored/pagesStored; старый recordsStored и
  исторические счётчики по-прежнему означают фотографии.
- Квитанции содержат только ID/версии/счётчики, без копии распознанного текста.
  После мутации клиент читает актуальные страницы через GET. Это также
  исключает сохранение удалённого содержимого в служебной истории повторов.

Маршруты и сервисы разделены; обработка текста/таблиц и удаление файлов
переиспользуются. Бизнес-логика не переносилась в компоненты интерфейса.

## Макет

[Открыть на обычном localhost](http://localhost:5173/multipage-preview.html).
Отдельная HTML-точка входа, не импортируется приложением и не включается
в обычную production-сборку. Используются реальные AppHeader, PhotoCard,
DocumentTextVariants, Modal и текущие CSS кнопок/диалогов.

Учебные данные: одна шапка, собственные вкладки каждой страницы, фото справа,
общая кнопка копирования, порядок, объединение/разделение и ошибки страницы.
Диалог общего копирования указывает номера страниц с выбранными таблицами.
Замена предлагается только при ошибке/отсутствии текста. При обработке общие
действия недоступны; нехватка остатка блокирует запуск всего выбранного набора.

Browser Plugin: просмотрены 1280/390/320 px, горизонтального переполнения страницы
нет. Проверены порядок, диалог таблиц/частичного текста, режим по умолчанию,
нехватка остатка, запрет смешанного объединения и допустимое объединение.
Ошибок JS нет; адресный ESLint пройден. Снимки сохранены в приватной work-папке.
Копирование, загрузка, повтор и замена в макете только показывают интерфейс;
запросы обработки не выполняются. Визуальная приёмка Ольгой ещё впереди.

Правки макета 16 ноября: собственные названия/аннотации страниц, номер и ссылка
«Убрать из документа» справа (страница сохраняется отдельной записью в архиве),
добавление рядом с датой и через привычный плавающий «+». Общая кнопка копирования
выделена справа от названия, на телефоне под ним; лишняя нижняя постраничная
кнопка убрана, остаётся существующая иконка вкладки. Новая раскладка проверена
на 1280/390/320 px; это по-прежнему макет для согласования.

Следом: согласовать макет; реализовать серверные загрузочные сессии и замену,
подключить загрузку/архив/чтение и общий алгоритм копирования. Отдельно проверить
бюджет перед расходующей обработкой и повторы двух вкладок (этап 5).
