# Различение одинаковых названий

2 ноября 2026 Ольга выбрала первую итерацию: добавлять номер к совпадающему
названию. «Копия» не используется: совпадение названий не доказывает повторную
загрузку файла или одного документа. Хеш изображения уже сохраняется в OCR-layout,
но пользовательского определения дублей по нему в этой итерации нет.

## Поведение

- Отдельное поле display_title хранит название записи: «Квитанция»,
  «Квитанция (2)», «Квитанция (3)». Регистр и пробельные различия не создают
  отдельную группу. При пустом названии используется «Запись».
- Название модели, распознанный текст и заголовки внутри оформленного документа
  сохраняются. В списке, на странице записи, при копировании названия и в поиске
  используется также название с номером. Копирование всего документа не добавляет
  номер в его содержимое.
- Номера существующих записей сохраняются после удаления соседней записи и
  повторной обработки с тем же названием. Освободившееся название может быть
  занято новой записью. При изменении самого названия выбирается свободное имя
  в новой группе.
- Названия независимы для аккаунтов и гостевых сессий. При переносе гостевых
  документов в аккаунт подпись сохраняется, если свободна; совпадения разрешаются
  новым номером. Операции защищены от параллельного назначения одного имени.
- Миграция 047 присваивает подписи также существующим документам по порядку
  загрузки. Дополнительных OCR/LLM-запросов нет.

## Проверки

7 новых проверок PostgreSQL в отдельной временной схеме прошли: существующие
документы и коллизия с настоящим названием «Квитанция (2)», разные владельцы,
удаление/повтор, изменение названия, десять одновременных загрузок, перенос
и разделение исходного/отображаемого заголовков. Существующие тесты гостевого
хранения и переноса прошли с новой миграцией. ESLint, node --check и сборка клиента
прошли. Browser Plugin на искусственных данных подтвердил номера в карточках
и странице, исходный заголовок во вкладке «Оформленный».

Замечание Ольги выявило пропуск в настоящем архивном списке: Gallery собирал
сокращённые данные и отбрасывал displayTitle в двух местах. Исправлены получение
из метаданных и подгрузка новых записей. Добавлена проверка рендера реального
Gallery; Browser Plugin подтвердил оба пути и сохранение номера при открытии
документа. Прежняя проверка напрямую через PhotoCard не покрывала этот переход.

Миграция применена только локально, локальный API перезапущен. Ручная приёмка
Ольгой, коммит и публикация ещё не выполнены.

```bash

npm run db:migrate
cd /root/myworld/client
npm run build
cd /root/myworld
pm2 restart myworld-server --update-env
pm2 status myworld-server
curl -fsS http://127.0.0.1:4000/api/health
```

Ожидаемая новая миграция: 047_document_display_titles.sql. Новых зависимостей
и переменных .env нет. Ольга проверяет одинаковые названия в гостевом режиме
и аккаунте, сохранение номера после удаления соседней записи, перенос после
входа и исходный текст при копировании из «Оформленный». Агент production
не подключает и не проверяет.
