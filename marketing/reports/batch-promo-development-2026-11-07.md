## Жизненный цикл намерения и возврат

1. Основной CTA ведёт только на `/?intent=batch&placement=batch_hero` либо
   `batch_final`. Продолжение одиночной пробы использует `batch_trial_result`.
   Произвольный return URL не читается, source/placement нормализуются по списку.
2. Намерение в `sessionStorage.word2you_pending_batch_upload` записывается только
   после выбора провайдера и существующего согласия. В нём source, placement и время;
   файлов, имён и персональных данных нет. Срок — 30 минут, область — текущая вкладка.
3. Email сохраняет текущий внутренний путь, OAuth-подобный возврат на `/` читает
   sessionStorage. После появления пользователя намерение удаляется **до** показа
   следующего шага. Служебные `intent=batch` и placement убираются из URL через replace;
   прочие query сохраняются. Нет автоматического клика input или обработки.
4. Закрытие email, ошибка OAuth/возврат гостем, истечение срока и начало другого
   входа очищают сохранённое намерение. Ошибочный email-код/отправку можно повторить
   в открытом диалоге; его закрытие отменяет намерение. После OAuth-ошибки только
   ручной повтор или переход к одному фото — автоматического входа/цикла нет.
5. Выбор файлов или Cancel диалога скрывают подсказку. Явная кнопка возврата
   отменяет шаг. Обновление обычной главной после успешного возврата его не повторяет.
6. При запрещённом sessionStorage вход остаётся доступен; email может использовать
   текущий batch URL. Перенос намерения через полный OAuth reload в таком браузере
   не гарантирован: останется обычный кабинет с существующей подсказкой пачки.

UTM/yclid/первый источник не перезаписываются; используются прежние acquisition
context и ClientID. Заглушки проверили их передачу и для email, и перед OAuth.

## Перед выпуском, команды и возврат

Работа шла в исходном `C:/Users/olgak/PROJECTS/myworld`, ветка `main`, без переключений,
worktree и копий проекта. На старте уже были чужие незавершённые клиентские,
серверные и документные правки. Они сохранены, коммитов/stage/push этой задачей нет.
На проверке HEAD `b14b3b5`, локальная main впереди известной origin/main на два
прежних документных коммита; свежесть remote не проверялась, fetch не выполнялся.

До безопасного выпуска: завершить визуальную приёмку локально через Browser Plugin,
просмотреть собственный diff и подготовить отдельный выборочный коммит. Нельзя
делать `git add .` или включать весь ROADMAP: он уже существенно изменён соседями.
Незавершённые `server/routes/authRoutes.js`, OCR и общий гостевой CTA этой задаче
для выпуска не нужны. Сборка текущего checkout содержит также чужие клиентские
правки; публиковать этот локальный dist целиком нельзя. Нужна сборка на сервере
из согласованного Git-состава.

Только после приёмки/согласованного коммита и отдельной команды Ольги, выполняет Ольга:

1. Локально: `git push origin main`.
2. Войти: `ssh root@147.45.246.205`.
3. На сервере: `cd /root/myworld`, затем `git status --short` и
   `git pull --ff-only origin main` (при незавершённых серверных правках остановиться).
4. Собрать: `npm run build --prefix client`. Без повторных VITE_INSPECTLET assignments.
5. Сверить выпуск: `git log -1 --oneline`,
   `test -s client/dist/.prerender/batch-photo-to-text.html`, `pm2 status myworld-server`.

Для этой клиентской правки **миграции, установка серверных зависимостей и рестарт
PM2 не требуются**. Команду `pm2 restart myworld-server` без другой необходимости
не выполнять. Реальную страницу, email/OAuth, выбор фото и события проверяет
только Ольга после публикации; агент production не открывал и не тестировал.

Возврат: если выпуск не принят — оставить изменения локально и не публиковать.
После выпуска — сделать отдельный `git revert` именно будущего согласованного
коммита этой задачи, затем те же push/pull/клиентская сборка. Точного хеша пока нет,
поэтому готовую команду revert с вымышленным хешем не приводим. Возврат не требует
отмены миграций: сервер/БД не менялись.
